Keep the agent configuration minimal, mount only credentials into tasks, and make routed tasks single-credential (issue #2190).

Three `--tool codex` runs ended with a question ("Should I proceed with this comprehensive scope?") instead of a pull request, one of them after 9.2 million input tokens. Each task had the host's whole `~/.codex` bind-mounted, and the host's `plugins/cache/openai-curated-remote/superpowers/6.3.0` — synced there by Codex's remote plugin catalog, never asked for by Hive Mind — told the model to run `brainstorming` before any action and wait for approval. The full analysis is in `docs/case-studies/issue-2190/`.

- **The global Claude/Codex configuration is audited and repaired at every start.** `src/agent-config-audit.lib.mjs` warns about and removes plugins, marketplaces, global skills and MCP servers other than Playwright from `~/.claude`, `~/.claude.json`, `~/.codex` and `~/.agents`. Codex now runs with `features.remote_plugin=false` and Claude with `CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL=1`, so the drift does not come back. `--no-agent-config-auto-repair` (or `HIVE_MIND_AGENT_CONFIG_AUTO_REPAIR=0`) keeps the warnings and skips the removal. Repository-local skills are untouched: a repository that ships a skill wants it.
- **A Docker-isolated task receives only credentials and session directories.** `~/.claude/.credentials.json`, `~/.codex/auth.json`, `projects/` and `sessions/` are bind-mounted — the very same files for every task, so a token refreshed anywhere is visible everywhere and transcripts stay auditable in one place. `~/.claude.json`, `settings.json`, `config.toml`, `plugins/`, `skills/` and `~/.agents` come from the image and die with the container.
- **`--playwright-skill`** deploys the Playwright CLI Agent Skill (`playwright-cli install --skills`) into the task workspace. The Playwright MCP stays on by default; with `--no-playwright-mcp` the skill can be the only browser path.
- **The router sidecar is no longer reachable from outside the task network.** It is created on the internal network, binds only the address it holds there (its entrypoint resolves its own alias and refuses `0.0.0.0`), and is connected to `bridge` for upstream access only afterwards. Verified against real Docker: loopback, a `bridge` container and the host are all refused while `api.github.com` still works. The router cannot do this natively; reported as [router#545](https://github.com/link-assistant/router/issues/545).
- **A task's token is revoked the moment its container exits**, for any reason, by a `docker wait` watcher — the 24 h / 5000-request limits are now only a backstop.
- **A routed task that switches to any credential other than the router token is stopped at once** with exit code 77 and a `Security violation (issue #2190)` message naming the file. The guard watches the Claude, Codex, `gh` and git credential surfaces once per second, starting before the CLI does anything. `HIVE_MIND_ROUTER_AUTH_GUARD=0` disables it for debugging the guard itself.
