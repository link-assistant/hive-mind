# Восстановление производственных задач

Telegram-бот, установленный на хосте `solve` и Docker-образ задач должны использовать проверенный выпуск. Обновление пакета на хосте не заменяет уже работающий бот или закешированный образ задач.

## Обновление и проверка

Во время инцидента в октябре 2026 года хост использовал версию 2.33.11, хотя исправление настроек рассуждения модели вышло в 2.33.13. Обновитесь до проверенного выпуска, содержащего это исправление и изменения восстановления из данного PR.

1. Запишите `solve --version`, `hive-telegram-bot --version`, образ задач и его дайджест. Проверьте опубликованную версию пакета командой `npm view @link-assistant/hive-mind version`.
2. Для установки через npm выполните `npm install -g @link-assistant/hive-mind@<version>`, затем перезапустите бот через существующий менеджер служб. Убедитесь, что служба использует обновлённый исполняемый файл, а не другую установку из PATH.
3. Загрузите выбранный тег `konard/hive-mind` или `konard/hive-mind-dind`. Явно обновите закреплённую ссылку на образ. В Coolify загрузите или пересоберите настроенный образ и повторно разверните приложение, сохранив подключения учётных данных и настройки задач.
4. Убедитесь, что стартовые сообщения хоста и следующей изолированной задачи показывают ожидаемую версию Hive Mind. Запишите дайджест образа вместе с версией хоста.
5. Запустите небольшую задачу с производственными настройками инструмента, модели и рассуждения. Настройки Codex проверяются по каталогу возможностей CLI до запуска; несовместимая конфигурация отклоняется до создания контейнера задачи.

## Аутентификация

Перед запуском Docker-задачи хост проверяет доступ к подписке Claude/Codex: до вспомогательных контейнеров, загрузки образов и создания контейнера задачи. При отказе аутентификации новый процесс CLI получает одну попытку обновить учётные данные, после чего проверка повторяется. Каждая проверка ограничена 15 секундами, процесс обновления — 20 секундами. Обновление может выполнить небольшой запрос к модели. Одновременные проверки одного инструмента и пути учётных данных используют общий запрос.

Если доступ не восстановлен, ошибка запуска и ответ Telegram предлагают повторно войти на хосте. Ожидающие задачи этого инструмента приостанавливаются до изменения файла учётных данных. Выполните `claude /login` или `codex login --device-auth` на хосте, предоставляющем подключённые файлы. Изменение файла разрешает следующей задаче повторную проверку. Очереди других инструментов продолжают собственные проверки. Работающая сессия Claude при потере доступа также запускает один новый процесс CLI для повторной попытки. Успешное обновление не выдаёт терминальный маркер остановки очереди.

Сбой API статистики и HTTP 429 не доказывают недействительность учётных данных. Задачи с API-ключом, маршрутизатором или Formal AI пропускают проверку подписки; API-ключ проверяется обычным выполнением запроса к провайдеру. Приостановка хранится в процессе бота и восстанавливается предварительной проверкой после перезапуска. Существующие процессы `/hive` останавливаются по терминальному маркеру доступа; после входа перезапустите `/hive`.

Проблемы inode, атомарной замены общих учётных данных и блокировки обновления отдельно рассматриваются в [#2296](https://github.com/link-assistant/hive-mind/issues/2296). Эта проверка и повторная попытка не меняют способ подключения файлов.

## Исчерпание повторных запусков и отказ модели

При исчерпании общего бюджета повторных запусков весь запуск завершается неуспешно, PR остаётся черновиком, публикуется одна сводка с оставшейся причиной блокировки и названиями неуспешных проверок CI. Комментарий сохраняет идентификатор коммита PR. Автоматическая постановка в очередь через `/hive --auto-continue` откладывает этот коммит на шесть часов. Переменная бота `HIVE_MIND_AUTO_RESTART_COOLDOWN_HOURS` меняет интервал; `0` отключает его. Новый коммит PR либо новые или отредактированные комментарии задачи, PR, строк кода и отзывы снимают задержку. Автоматические сообщения сессий и журналов её не снимают. Отложенные задачи доступны для проверки в последующих итерациях очереди. Ручной `solve` остаётся доступным.

Отказ Codex по причине риска кибербезопасности — терминальная ошибка. Отчёт в задаче или PR объясняет отказ модели и предлагает `--tool claude` или другую формулировку запроса. Цикл повторных попыток временных ошибок не запускается.

## Сохранение работы и остановленные контейнеры

Восстановление после критической ошибки создаёт снимок подходящей незакоммиченной работы в `recovery/<task-branch>` через отдельный индекс Git и отправляет его на сервер. Ветка PR, рабочее дерево и обычный индекс остаются доступными следующей сессии. Неотслеживаемые двоичные файлы размером до 5 МиБ сохраняются, включая снимки экрана и тестовые данные в `docs/`, `tests/`, `fixtures/` и `experiments/`. Расширение или байт NUL сами по себе не означают результат сборки. Известные каталоги сборки исключаются; слишком большие или нечитаемые файлы получают явную причину пропуска и запрещают подтверждение полного сохранения.

При `HIVE_MIND_KEEP_TASK_CONTAINER=on-failure` монитор завершения удаляет контейнер после ошибки аутентификации, отказа модели или исчерпания бюджета только при наличии системной записи о загрузке журналов и полном удалённом сохранении работы. Отправленный коммит восстановления включает историю родительского коммита; для чистого дерева без такого коммита HEAD должен совпадать с удалённой веткой задачи. Ошибки загрузки, отправки, неизвестное состояние сохранения, слишком большие файлы и неотправленные коммиты сохраняют контейнер. Неполное удалённое сохранение также отключает автоматическое удаление рабочего каталога, чтобы работа оставалась внутри контейнера. `always` всегда сохраняет контейнер. Завершающее удаление использует `docker rm` без принудительного режима, который отказывается удалять возобновлённый контейнер. Политика `none` по-прежнему доступна.

Включите `--attach-logs`, чтобы разрешить очистку на основании сохранённых данных. Независимое управление жизненным циклом start-command, сканирование TTL и удаление образов восстановления рассматриваются в [#2629](https://github.com/link-assistant/hive-mind/issues/2629) и [#2630](https://github.com/link-assistant/hive-mind/issues/2630).

## Код выхода 137

Сам по себе код 137 не доказывает остановку из-за нехватки памяти. Используйте существующую диагностику cgroup `memory.events`/`oom_kill` и состояние Docker из отчёта завершения. Перед увеличением памяти или swap проверьте лимит контейнера и свободные ресурсы хоста. Это изменение не меняет производственные лимиты или существующее восстановление после OOM. При неполном сохранении оставьте контейнер и исследуйте указанную ошибку до удаления.
