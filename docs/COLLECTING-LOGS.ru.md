# Сбор журналов (languages: [en](COLLECTING-LOGS.md) • [zh](COLLECTING-LOGS.zh.md) • [hi](COLLECTING-LOGS.hi.md) • ru)

Hive Mind пишет свидетельства своей работы в нескольких местах, и ни одно из них по отдельности не рассказывает историю запуска целиком. Когда вы разбираетесь со сбоем — или проверяете, что именно сделал автономный агент, — нужны все. На этой странице собран полный список и скрипт, который его обходит.

```bash
node examples/collect-logs.mjs --list                  # показать все места, ничего не копируя
node examples/collect-logs.mjs --out ./audit           # собрать их в ./audit
node examples/collect-logs.mjs --out ./audit --session <uuid>   # плюс консольный журнал этой сессии
```

Рядом с собранным скрипт пишет `INDEX.md`, где отмечено, что вошло в архив, что пропущено и что содержит каждое место. Список, который он обходит, — это `describeSystemLogLocations()` из `src/router-logs.lib.mjs`, тот же самый, что описан на этой странице: он хранится в коде, чтобы страница и скрипт не разошлись.

## Где что лежит

| Место                  | Путь                                                                      | Что содержит                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Журналы запусков**   | Рабочий каталог либо `--log-dir` / `HIVE_MIND_LOG_DIR`                    | По одному `solve-*.log` / `hive-*.log` на запуск; файл переименовывается в `<sessionId>.log`, как только ИИ-инструмент сообщает идентификатор сессии. История одного запуска. |
| **Журналы бота**       | `~/.hive-mind/logs` (`HIVE_MIND_LOG_DIR`)                                 | Ротируемый `telegram-bot.log` и резервные копии с отметками времени: каждая команда, каждый запуск и каждое событие жизненного цикла, которые обработал бот.                  |
| **Состояние бота**     | `~/.hive-mind/state` (`HIVE_MIND_STATE_DIR`)                              | Отслеживаемые сессии и состояние sidecar, включая `router-sidecar.json` — какая задача каким токеном владела и когда. **Содержит секрет подписи роутера; права `0600`.**      |
| **Консоль сессии**     | `/tmp/start-command/logs/isolation/<backend>/<uuid>.log`                  | Вывод консоли изолированной сессии. Именно это отдаёт команда Telegram `/log <uuid>`.                                                                                         |
| **Журналы контейнера** | `docker logs <sessionId>`                                                 | Собственная запись stdout/stderr контейнера задачи, доступная до удаления контейнера.                                                                                         |
| **Запросы роутера**    | `hive-mind-router-data:/data/router/requests/<token-hash>/requests.jsonl` | По одному JSONL-журналу запросов с редактированием на каждый выпущенный токен, то есть на каждую задачу. Сохраняется после отзыва токена.                                     |
| **Аудит роутера**      | `hive-mind-router-data:/data/router/audit.jsonl`                          | События выпуска, отзыва и ротации токенов.                                                                                                                                    |
| **Сессии задач**       | `hive-mind-router-data:/data/router/task-sessions/<sessionId>/`           | Данные сессии агента, выгруженные из каждой задачи с роутером до удаления её контейнера: записи того, что агент действительно делал.                                          |

Последние три существуют только при использовании [`--use-router`](./ROUTER.ru.md).

## Каталог состояния — не то свидетельство, которым можно делиться

В `~/.hive-mind/state` лежит секрет, которым подписываются токены роутера. Любой, у кого он есть, может выпускать токены к подписке. Поэтому `examples/collect-logs.mjs` **никогда его не копирует** — он печатает путь, чтобы вы знали, где каталог находится, и оставляет его на месте. Если для расследования нужен факт оттуда, извлеките именно этот факт, а не каталог целиком.

Всем остальным из списка делиться можно — с обычной оговоркой: Hive Mind [маскирует распознанные учётные данные](./CREDENTIAL-SANITIZATION.ru.md) на собственных путях вывода, а роутер редактирует тела запросов, но ни то, ни другое не заменяет чтения архива перед тем, как приложить его к публичной задаче.

## Как прочитать журналы роутера, когда роутер не запущен

Данные роутера живут в именованном томе `hive-mind-router-data`, а не в контейнере. Том переживает любой писавший в него контейнер, и Hive Mind его никогда не удаляет — но сам sidecar останавливается, как только перестаёт быть нужен задачам, поэтому в момент, когда вам понадобились журналы, спрашивать обычно уже некого.

Оба случая предусмотрены:

```bash
# Когда sidecar работает — копируем прямо из него:
docker cp hive-mind-router:/data/router/. ./audit/router

# Когда не работает — монтируем том в одноразовый контейнер:
docker run --rm --entrypoint cp \
  -v hive-mind-router-data:/data/router:ro \
  -v "$PWD/audit/router:/export" \
  --user "$(id -u):$(id -g)" \
  ghcr.io/link-assistant/router:latest -a /data/router/. /export/
```

`collectRouterLogs()` из `src/router-logs.lib.mjs` пробует первый способ и при неудаче переходит ко второму. Обратите внимание на две детали безопасности во втором варианте — их стоит сохранить, если запускаете команду вручную: том монтируется **только для чтения**, поэтому сбор доказательств не может их испортить, а `--user` делает выгруженные файлы читаемыми без прав root.

## Как найти нужный запуск

- **Из Telegram:** `/log <uuid>` сразу отдаёт консольный журнал сессии; `/status` перечисляет живые сессии и их uuid.
- **По идентификатору сессии:** после того как инструмент сообщил свой идентификатор, журналы запусков называются `<sessionId>.log`, поэтому `grep -rl <sessionId>` по каталогу журналов находит все файлы об этом запуске.
- **Из задачи с роутером:** `router-sidecar.json` в каталоге состояния сопоставляет идентификаторы сессий с идентификаторами токенов, а идентификатор токена — это имя каталога внутри `requests/`.

## Хранение

Ничто из перечисленного не ротируется автоматически, кроме журнала бота, который хранит резервные копии с отметками времени. Журналы запусков, консольные журналы сессий и том роутера растут, пока вы их не удалите. Журналы контейнера исчезают вместе с контейнером.

Если журнал аудита нужно сохранять, по расписанию копируйте том роутера в надёжное место: это единственное место, задуманное как полное.
