# Missing Codex Code Mode host in a Hive Mind solve

Hive Mind 2.50.0 activated a native Codex 0.164.0 generation containing the adapted CLI alone. Codex tried to execute a required Code Mode cell, failed to find its sibling `codex-code-mode-host`, and completed its language-model turn. Hive Mind suppressed the infrastructure error and ran two more sessions with the same installation. The restart guard then reported `no-progress`. The container exited 1 with a peak of 853,827,584 bytes against a limit of 3,135,365,120 bytes and zero cgroup OOM events or kills. [Original incident](https://github.com/link-assistant/hive-mind/issues/4173)

The [evidence inventory](artifacts.json) identifies the original downloads and the reported hashes of the collector's raw files. [Incident observations](observations.json) point to original source lines. The [Codex event replay](codex-events.ndjson) keeps the protocol payloads with the install path replaced. The linked public records retain the full transcripts. The checked-in excerpts omit account data, unrelated executions, machine labels and network details. All seven published incident log and bundle sources were downloaded. The raw host copies of the files listed inside the bundle were available as published text and collector metadata.

## Root causes and remedies

### Runtime installation

The root and DinD Dockerfiles installed the pinned OpenAI npm launcher and then activated the Hive Mind build. The native installer allowed exactly the CLI and its provenance and licence files. Activating it bypassed the OpenAI launcher and changed the executable's real directory. The required host lookup defaults to a sibling of the live CLI, so the stock platform asset beside the original CLI could no longer be found. None of the three turns executed their requested shell work. The same install and admission modules serve both native Docker layouts, model-catalogue queries, selected-auth preflight and the installed agent verifier. The Coolify image uses the complete stock layout. [Native adaptation](https://github.com/link-assistant/hive-mind/pull/3786) · [Upstream host selection and diagnostic](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/core/src/tools/code_mode/mod.rs) · [Stock launcher](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-cli/bin/codex.js)

The installer now obtains the companion from the installed matching OpenAI platform alias, validates its version, ELF machine, size and SHA-256, and stages it next to the verified CLI. The recipe pins those bytes for both Linux architectures. npm and the standalone upstream release contain the same executable bytes. Staging and installed admission check both files. Legacy activation publishes a new generation and then switches the selected command link. Existing configs, credentials and session histories are outside these generations. The default-off `HIVE_MIND_NATIVE_CODEX_DEBUG=1` setting exposes the failed admission phase and system error code without machine paths. [Installer](../../../src/native-codex-runtime.lib.mjs) · [Recipe](../../../src/native-codex/recipe.json) · [Operator documentation](../../../src/native-codex/PACKAGES.md)

Upstream's separate platform npm packages and release assets already solve native distribution. The incident workaround is to install the matching stock optional dependency, place the verified companion beside the adapted executable, and validate with an actual cell. The patched activation handles that automatically offline. Shipping an extra executable inside each Hive Mind variant would add about 27 MiB compressed and threaten the 157 MiB publish cap that led to split packages. Compiling a companion from source adds a build dependency and still requires verifying the packaged layout. Pointing Codex at an arbitrary host with an environment override would add a dependency on mutable execution settings. Reusing the pinned asset keeps the release size and native provenance checks. [Release assets](https://github.com/openai/codex/releases/tag/rust-v0.164.0) · [Package size incident](https://github.com/link-assistant/hive-mind/pull/4051)

Hive Mind issue 4159 describes the same missing sibling on the same Universal Translator run. The reporter confirmed tool execution in a manually repaired task image. Its draft PR 4160 stopped before modifying the native runtime. The automatic activation here covers the same defect and verifies the companion on both supported architectures. [Related incident](https://github.com/link-assistant/hive-mind/issues/4159) · [Live workaround](https://github.com/link-assistant/hive-mind/issues/4159#issuecomment-7203484800) · [Earlier draft](https://github.com/link-assistant/hive-mind/pull/4160)

### Completed turn with a failed runtime

In Code Mode-only configuration, Codex reports the bootstrap failure as an error item, returns a failed cell to the model and can finish the turn and exit zero. Hive Mind's permissive rule for stray or recovered errors, introduced for issue 1955, discarded this genuine failure. The solver now treats the pinned upstream fail-closed diagnostic as terminal and gives task reporting the `codex-code-mode-host` signature. The same stdout event handler serves primary, resumed and automatic restart sessions. The narrow match preserves the upstream optional direct-tool fallback and ordinary recovered item errors. The no-progress guard still handles genuine repeated stalls. [Original false positive](https://github.com/link-assistant/hive-mind/issues/1955) · [Shared task signatures](https://github.com/link-assistant/hive-mind/pull/4129) · [Upstream Code Mode test](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/core/tests/suite/code_mode.rs)

The offline probe observed exit zero and `turn.completed` with the stock 0.164.0 and 0.172.0 CLI and with Hive Mind's adapted 0.164.0 CLI. The identical constant cell returned its marker after staging the released host next to the adapted executable. A stable upstream runtime error code paired with the session's failure status would let clients rely on structured state. Parsing the specific fail-closed diagnostic is the compatibility path for this pinned version. [Loopback probe](../../../experiments/issue-4173/probe-code-mode-host.mjs) · [Upstream report](https://github.com/openai/codex/issues/64358)

### Reporting and Docker comparison

The collector found one unmatched Docker-tail row out of 80. Docker line 1416 matches the published 36,029-byte size and exact digest. Decoding its three concatenated JSON values gives the same issue, comments array and PR identity as wrapper line 1440. The PR title and nested base repository metadata differ, while the head and base commit IDs match. Both streams captured all three host failures and the exit verdict. There is no attributed exit-time OOM or Docker restart associated with this container. [Docker log](https://gist.github.com/konard/fadc5aa4306a7fc7f806da90fa7009b8) · [Wrapper log](https://gist.github.com/konard/8c3569c0fc37b7c0b02f53a425451ed7) · [Comparison reported upstream](https://github.com/link-assistant/hive-mind-control-center/issues/5#issuecomment-7224777881)

The affected Universal Translator issue was workload context. The recovered change in the later run and the different terminal error there show a separate execution. The later sanitizer failure is tracked independently. The upstream Codex issue addresses the machine-readable outcome of the failed host bootstrap. The existing Control Center issue addresses comparing streams with different record framing. [Sanitizer incident](https://github.com/link-assistant/hive-mind/issues/4176)
