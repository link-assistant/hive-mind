# Организация открытых задач

Telegram-команда `/organize` классифицирует все открытые задачи одного GitHub-
репозитория: назначает существующий Issue Type организации и корректирует
существующие метки репозитория. Это обслуживание метаданных, а не решение задач.

## Использование и значения по умолчанию

```text
/organize https://github.com/owner/repository
/organize https://github.com/owner/repository --dry-run
/organize https://github.com/owner/repository --tool codex --model gpt-5.6-sol --think high
Считайте примеры и руководства по миграции документацией.
```

Можно ответить `/organize` на сообщение с URL репозитория. Принимается только
один репозиторий; обрабатываются все и только открытые задачи, без pull request.
По умолчанию проверенные изменения применяются. `--dry-run` показывает тот же
полный план и diff без записи. `TELEGRAM_ORGANIZE=false` отключает команду.

Команда доступна только в разрешённых группах и темах. Учётной записи `gh` нужны
права чтения и как минимум triage/write/maintain/admin. Тексты задач, комментарии,
связанные PR, README и заметки оператора считаются недоверенными данными и не
попадают в фиксированный system prompt. Модель не получает GitHub-токен или
инструмент записи и возвращает только план, который приложение строго проверяет.

Перед записью повторно проверяется `updatedAt`; более новая правка человека
приводит к пропуску. Изменения идут ограниченными пакетами, частичный результат
читается перед повтором, а итоговые типы и точный набор меток проверяются полным
повторным чтением. Ответы проходят проверку секретов, минимальный audit хранится
в `organize-audits/` каталога состояния Hive Mind.

Меняться могут только Issue Type и набор уже существующих меток. Полезные
сторонние метки сохраняются. Команда не создаёт типы/метки, не назначает людей,
не меняет milestone, title или body, не комментирует и не закрывает задачи, не
меняет код, не создаёт ветку или pull request. Недоступная таксономия явно
указывается. Повторный запуск без изменений не выполняет записей.
