Router monitoring across command startup and logging, 2026-10-31 UTC

Root cause: monitoring in the four additional adapters started when the output
iterator was consumed. Agent streaming input can start the native process while
attaching stdin, before logging and output consumption. Logging failure could
therefore abandon a running command. A violation detected during logging could
also disappear before ordinary error recovery rechecked the filesystem.

The strict reproduction imports the actual Agent, OpenCode, Gemini and Qwen
adapters with isolated synthetic environments. Forty-eight bounded mocked
commands cover new/resumed execution, environment/argv selection, persistent
and subsequently removed credentials, and ordinary logging failure. Two actual
Agent streaming-input controls use command-stream 2.6.0 and a finite Node parent
and child with 32 MiB heaps. Both processes must stop during pending logging
after a security violation, or before an ordinary failed attempt returns.
Fixture cleanup always kills and verifies termination. No provider or live
credential is involved. Each test has a ten-second deadline.
