# लॉग एकत्र करना (languages: [en](COLLECTING-LOGS.md) • [zh](COLLECTING-LOGS.zh.md) • hi • [ru](COLLECTING-LOGS.ru.md))

Hive Mind साक्ष्य कई अलग-अलग जगहों पर लिखता है, और उनमें से कोई एक भी अकेले किसी रन की पूरी कहानी नहीं बताती। जब आप किसी विफलता की जाँच कर रहे हों — या यह ऑडिट कर रहे हों कि किसी स्वायत्त एजेंट ने क्या किया — तब आपको वे सब चाहिए। यह पृष्ठ वही पूरी सूची है, और वह स्क्रिप्ट भी जो उसे पूरा घूम आती है।

```bash
node examples/collect-logs.mjs --list                  # हर स्थान दिखाएँ, कुछ भी कॉपी न करें
node examples/collect-logs.mjs --out ./audit           # उन्हें ./audit में इकट्ठा करें
node examples/collect-logs.mjs --out ./audit --session <uuid>   # साथ में उस session का console लॉग
```

स्क्रिप्ट जो एकत्र करती है उसके साथ ही एक `INDEX.md` लिखती है, जिसमें दर्ज होता है कि क्या शामिल हुआ, क्या छोड़ा गया, और हर स्थान में क्या रहता है। जिस सूची पर वह चलती है वह `src/router-logs.lib.mjs` का `describeSystemLogLocations()` है — वही सूची जिसे यह पृष्ठ दस्तावेज़ करता है, कोड में रखी गई ताकि दोनों एक-दूसरे से अलग न हो जाएँ।

## स्थान

| स्थान               | कहाँ                                                                      | उसमें क्या है                                                                                                                                                               |
| ------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **रन लॉग**          | कार्य डायरेक्टरी, या `--log-dir` / `HIVE_MIND_LOG_DIR`                    | प्रति रन एक `solve-*.log` / `hive-*.log`; AI टूल द्वारा session id बताते ही उसका नाम `<sessionId>.log` कर दिया जाता है। एक रन का पूरा वृत्तांत।                             |
| **बॉट लॉग**         | `~/.hive-mind/logs` (`HIVE_MIND_LOG_DIR`)                                 | Rotate होने वाला `telegram-bot.log` और timestamp वाली बैकअप प्रतियाँ: बॉट द्वारा संभाला गया हर command, हर launch और हर lifecycle event।                                    |
| **बॉट state**       | `~/.hive-mind/state` (`HIVE_MIND_STATE_DIR`)                              | ट्रैक की गई sessions और sidecar की स्थिति, जिसमें `router-sidecar.json` भी है — किस कार्य के पास कौन-सा टोकन था और कब। **इसमें राउटर का signing secret है; अनुमति `0600`।** |
| **Session console** | `/tmp/start-command/logs/isolation/<backend>/<uuid>.log`                  | किसी आइसोलेटेड session का console आउटपुट। Telegram का `/log <uuid>` कमांड यही देता है।                                                                                      |
| **कंटेनर लॉग**      | `docker logs <sessionId>`                                                 | कार्य कंटेनर के stdout/stderr की Docker द्वारा की गई अपनी रिकॉर्डिंग, कंटेनर हटने तक उपलब्ध।                                                                                |
| **राउटर अनुरोध**    | `hive-mind-router-data:/data/router/requests/<token-hash>/requests.jsonl` | प्रति जारी टोकन — यानी प्रति कार्य — एक redacted JSONL अनुरोध लॉग। टोकन रद्द होने के बाद भी सुरक्षित।                                                                       |
| **राउटर ऑडिट**      | `hive-mind-router-data:/data/router/audit.jsonl`                          | हर अधिकृत अनुरोध के लिए एक पंक्ति: समय, टोकन id, session लेबल, provider, surface, path और मॉडल।                                                                             |
| **कार्य sessions**  | `hive-mind-router-data:/data/router/task-sessions/<sessionId>/`           | राउटर वाले हर कार्य के कंटेनर को हटाने से पहले उससे निकाला गया एजेंट का session डेटा: एजेंट ने वास्तव में क्या किया इसका लेखा।                                              |

अंतिम तीन केवल तभी होते हैं जब [`--use-router`](./ROUTER.hi.md) उपयोग में हो।

## State डायरेक्टरी ऐसा साक्ष्य नहीं जिसे साझा किया जा सके

`~/.hive-mind/state` में वह secret है जो राउटर के टोकन पर हस्ताक्षर करता है। जिसके पास यह हो वह सदस्यता के विरुद्ध टोकन जारी कर सकता है। इसीलिए `examples/collect-logs.mjs` उसे **कभी कॉपी नहीं करता** — वह केवल पथ छापता है ताकि आप जानें कि वह कहाँ है, और उसे वहीं छोड़ देता है। यदि किसी जाँच के लिए उसमें से कुछ चाहिए, तो पूरी डायरेक्टरी नहीं, वह विशिष्ट तथ्य निकालें।

सूची की बाक़ी हर चीज़ साझा की जा सकती है, सामान्य समीक्षा के अधीन: Hive Mind अपने आउटपुट पथों पर [पहचाने गए क्रेडेंशियल छिपा देता है](./CREDENTIAL-SANITIZATION.hi.md), और राउटर अनुरोधों के body redact करता है, पर इनमें से कोई भी उस बात का विकल्प नहीं कि किसी सार्वजनिक issue से संग्रह जोड़ने से पहले आप उसे स्वयं पढ़ लें।

## जब कोई राउटर नहीं चल रहा हो तब राउटर लॉग पढ़ना

राउटर का डेटा named वॉल्यूम `hive-mind-router-data` में रहता है, कंटेनर में नहीं। यह वॉल्यूम उसमें लिखने वाले हर कंटेनर से अधिक जीता है और Hive Mind इसे कभी नहीं हटाता — लेकिन sidecar स्वयं तभी तक चलता है जब तक किसी कार्य को उसकी ज़रूरत है, इसलिए जिस क्षण आपको लॉग चाहिए, प्रायः पूछने के लिए कुछ चल ही नहीं रहा होता।

दोनों स्थितियाँ संभाली गई हैं:

```bash
# जब sidecar चल रहा हो — सीधे उसी से कॉपी करें:
docker cp hive-mind-router:/data/router/. ./audit/router

# जब न चल रहा हो — वॉल्यूम को एक बार इस्तेमाल होने वाले कंटेनर में mount करें:
docker run --rm --entrypoint cp \
  -v hive-mind-router-data:/data/router:ro \
  -v "$PWD/audit/router:/export" \
  --user "$(id -u):$(id -g)" \
  ghcr.io/link-assistant/router:0.109.0 -a /data/router/. /export/
```

`src/router-logs.lib.mjs` का `collectRouterLogs()` पहला तरीका आज़माता है और विफल होने पर दूसरे पर लौट आता है। दूसरे तरीके की दो सुरक्षा बारीकियाँ ध्यान देने योग्य हैं, और कमांड हाथ से चलाते समय उन्हें बनाए रखना चाहिए: वॉल्यूम **read-only** mount होता है, इसलिए साक्ष्य एकत्र करना उन्हें कभी नुक़सान नहीं पहुँचा सकता, और `--user` से निर्यात की गई फ़ाइलें root के बिना पढ़ी जा सकती हैं।

## अपनी वांछित रन ढूँढ़ना

- **Telegram से:** `/log <uuid>` सीधे session console लॉग देता है; `/status` जीवित sessions और उनके uuid सूचीबद्ध करता है।
- **Session id से:** टूल द्वारा अपना id बताने के बाद रन लॉग का नाम `<sessionId>.log` हो जाता है, इसलिए अपनी लॉग डायरेक्टरी में `grep -rl <sessionId>` उस रन से जुड़ी हर फ़ाइल ढूँढ़ देता है।
- **राउटर वाले कार्य से:** state डायरेक्टरी का `router-sidecar.json` session id को token id से जोड़ता है, और token id ही `requests/` के नीचे डायरेक्टरी का नाम है।

## संरक्षण

बॉट लॉग को छोड़कर, जो timestamp वाली बैकअप प्रतियाँ रखता है, यहाँ कुछ भी स्वयं rotate होकर नहीं हटता। रन लॉग, session console लॉग और राउटर वॉल्यूम तब तक बढ़ते रहते हैं जब तक आप उन्हें न हटाएँ। कंटेनर लॉग कंटेनर के साथ ही चले जाते हैं।

जिस ऑडिट रिकॉर्ड को आप रखना चाहते हैं, उसके लिए राउटर वॉल्यूम को नियमित रूप से किसी टिकाऊ जगह कॉपी करें — यही एकमात्र स्थान है जिसे पूर्ण होने के लिए बनाया गया है।
