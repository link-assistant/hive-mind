## Root causes

1. **Top-level `git status` only.** A submodule shows up in the parent as one ` M modules/x` line at most. Commits that the parent already records but that no remote has do not show up at all. Every check counted paths in the parent only.
2. **Gitlinks were recorded blindly.** The private-index snapshot (`git add -u`) and the auto-commit (`git add -A`) store each submodule's local `HEAD` as the parent's gitlink and push it. A checkout of that parent commit then fails with `not our ref`, and the real work stays on the killed machine.
3. **Nothing checked the pointers before "ready".** `verifyResults` marked the PR ready without asking whether `.gitmodules` URLs serve the recorded commits.
4. **#3572.** solve sets `cleanupContext.branchName` only after `createOrCheckoutBranch`. The dirty-tree check of a reused working directory (`verifyDefaultBranchAndStatus`, `src/solve.repo-setup.lib.mjs:285` at the time) throws earlier. `handleFailure` then called the preservation with `branchName: null`. `recoveryBranchFor(null)` returned the shared name `recovery/detached-head`, and the push was skipped whenever `branchName` was missing. solve did know the PR branch: it had resolved `prBranch` from the PR URL (`src/solve.mjs:355`).
5. **#3656.** The private index was built with `GIT_INDEX_FILE=tmp git read-tree HEAD`. Such an index has no stat data, so the following `git add -u` reads and hashes every tracked file. That took 40 s on a container at load 8 on 6 CPUs, with cgroup memory at 2.9 GB of 2.9 GB. Every status line in that run was `.claude/worktrees/agent-*` (AI tool state), so all of that work led to "nothing to preserve".

## Solution

| Place                                                         | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `git-submodules.lib.mjs`                                      | `git submodule foreach --quiet --recursive` lists submodules. Each one is checked with `git status --porcelain --untracked-files=all` and `git rev-list HEAD --not --remotes`. Without `.gitmodules`, no command runs.                                                                                                                                                                                                |
| Restart and pre-session checks, session-change measurement    | Submodule work is listed after the top-level lines as `## <path>: N uncommitted file(s), M commit(s) on no remote`, followed by its files. The restart feedback explains how to commit inside each submodule.                                                                                                                                                                                                         |
| Critical-error preservation (`critical-error-commit.lib.mjs`) | Innermost first, each dirty submodule gets a snapshot commit (private index; its `HEAD` and worktree are not changed) on `recovery/<branch>`, pushed to its `origin`, or to a GitHub fork if that is refused. The parent's recovery commit records only pointers whose commit reached a remote. Every other pointer stays at the parent `HEAD`'s value, and a `❌` line says so.                                      |
| Kill/interrupt auto-commit (`submodule-uncommitted.lib.mjs`)  | Wraps every tool's `checkForUncommittedChanges`. It commits and pushes inside the submodules first, then lets the tool commit the parent. A submodule that reached no remote keeps its old pointer. Gitlinks that `.gitmodules` does not list (#3572) are unstaged by the shared `unstageUnregisteredGitlinks`.                                                                                                       |
| Ready check (`submodule-pointers.lib.mjs`, `verifyResults`)   | Every gitlink changed since the PR base must be fetchable from its `.gitmodules` URL: first `git ls-remote`, then a fetch of the remote's branches and tags into a scratch repository. Unreachable commits are pushed under the PR branch name, or to a fork with a pull request in the submodule repository, linked from the parent PR description. Anything still unreachable keeps the PR a draft, with a comment. |
| Recovery branch name (#3572)                                  | The order is: `branchName`, then the PR branch solve resolved (`cleanupContext.prBranch` → `fallbackBranchName`), then the checked-out branch (`git symbolic-ref --short -q HEAD`), then `recovery/detached-<sha8>-<UTC time>`. The branch is pushed in every case.                                                                                                                                                   |
| Private index (#3656)                                         | The temporary index is a copy of the real index (`git rev-parse --git-path index`, then `copyFile`), so `git add -u` hashes only files whose stat data changed, and staged-only files are kept. `git read-tree HEAD` is only the fallback when there is no real index. When there is no submodule work and every status line is AI tool state, the step returns before any index work.                                |

## Remaining limits

- If a submodule's `origin` refuses the recovery commit, the commit is pushed to a fork but no pull request is opened. On GitHub the commit can still be fetched through the fork network; on other hosts it cannot.
- The ready check runs once per `verifyResults`. If a submodule commit is later force-pushed away, the pull request is not re-checked.
- Fork pull requests in submodule repositories are created with `gh pr create`. GitHub makes a fork's commits fetchable from the upstream only after a short delay, so the check right after publishing can still fail. The PR then stays a draft, and the next run publishes it.
- The #3656 early skip applies only when every status line is AI tool state. In a mixed snapshot, a tracked AI-tool gitlink (such as the five `.claude/worktrees` gitlinks already on PR #3531) is still updated by `git add -u`, but only on the recovery branch, never on the PR branch.
