# Case study: issue #3215 — Formal AI Hello World via `/claude`, `/codex`, `/agent`

On 2026-10-13 the same Hello World task was sent from Telegram three times, once per tool, with `--model formal-ai`:

```
/<claude|codex|agent> <issue-url> --model formal-ai --attach-logs --verbose --no-tool-check --disable-report-issue --isolation docker
```

Runtime: `solve v2.35.8`, task image `konard/hive-mind-dind:2.35.8`, start-command 0.37.1, `@link-assistant/agent` 0.26.13, Formal AI 0.352.1 (baked into the image).

None of the three runs did what Telegram said it did:

| Command   | Repository (language) | Telegram said                               | Reality                                                                                                               |
| --------- | --------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `/codex`  | Rust                  | ✅ after 11 s, then "⏳ Executing…" forever | The bot froze for every chat during the image pull. 213 `gh issue view` calls. Restart hit ChatGPT, exit 1 unreported |
| `/agent`  | Scala                 | ❌ exit 1                                   | A recoverable `File not found: …/e.g` tool error was treated as fatal                                                 |
| `/claude` | Kotlin                | ✅ 4m 19s, PR marked ready, 🎉 SUCCESS      | 2 turns, no commit by this session; the "summary" was the raw output of `pwd`                                         |

The same evening, a `/claude` run on `Godmy/stylist-svelte#5` was OOM-killed. Its in-place resume ran the Telegram alias `/claude` as a program (exit 127, #2630), and its nested dockerd refused to start because of a stale `/var/run/docker.pid` (#3214).

In CI, the `Formal AI Draft` workflow failed on 53 of the last 60 issues (#3248). The cause is the same `e.g` chain (formal-ai#1189 → agent#332 → #3213).

The logs are in private gists, so this directory quotes only the lines needed, with `log:line` references:

## Remaining dependencies

These issues are outside this repository. They do not block the fixes here:

- link-assistant/agent#332: failed tool calls were emitted as fatal top-level `error` events. **Fixed in 0.26.14**; this PR pins 0.26.15, the current release. Hive Mind also stops treating a tool error event as fatal on older agents (#3213).
- link-assistant/formal-ai#1189: Formal AI reads the literal path `e.g` from issue prose.
- link-assistant/formal-ai#1205, #1206, #1207: the Formal AI side of these runs (looping on `gh issue view`, asking the user to "Report issue").
- link-assistant/formal-ai#1208, #1209, #1211: from CI. Derivation records are written into the user's repository, a `planned_not_executed` regression, and garbage files are written and claimed as verified.
- link-assistant/formal-ai#1203: 0.353.2 is on crates.io and ghcr without a GitHub Release.

## Reproduction

The original failures need a Telegram bot, a Docker host and a ~7 GB Formal AI image. Each one is reduced to a unit test that passes on this branch and fails on `main`. On `main` it fails either on an assertion or because the module with the fix does not exist yet:

```bash
npm ci
for t in \
  tests/telegram-handler-nonblocking-3206.test.mjs \
  tests/session-launch-observation-3209.test.mjs \
  tests/formal-ai-sidecar-lease-3210.test.mjs \
  tests/formal-ai-image-local-first-3207.test.mjs \
  tests/formal-ai-accepted-fallback-3208.test.mjs \
  tests/session-changes-3211.test.mjs \
  tests/working-session-summary-echo-3211.test.mjs \
  tests/codex-formal-ai-restart-3212.test.mjs \
  tests/agent-recoverable-tool-error-3213.test.mjs \
  tests/dind-stale-pid-cleanup-3214.test.mjs \
  tests/issue-2630-alias-recovery.test.mjs \
  tests/issue-2630-resume-startup.test.mjs \
  tests/log-upload-failure-location-3248.test.mjs \
  tests/formal-ai-draft-checks-3248.test.mjs \
  tests/formal-ai-draft-health-3248.test.mjs; do
  node "$t" || echo "FAILED: $t"
done
```

The end-to-end check is the issue's own scenario, run from Telegram on a host with this build:

1. `/claude <hello-world issue URL> --model formal-ai`, then the same with `/codex` and `/agent`.
2. While they run, send `/help` and `/sessions`. The bot answers at once.
3. Each run ends with a pull request, or with a failure message that names the real reason. No message says ✅ before the container has run.
4. `docker kill` a DinD session container and `/resume` it. `dockerd` starts again (#3214), and the alias recovery runs `solve`, not `/claude` (#2630).
