# Case study for issue #4052

The automatic Control Center reporter filed 24 report entries covering 15 distinct Docker execution UUIDs, each on attempt 1. All exited 1 and all received the signature `failed`. Their logs identify six causes. Each reported Docker state had `OOMKilled=false` and each reported cgroup had zero `oom` and `oom_kill` events. Several runs approached their memory limits. The reports contain no attributed host OOM or daemon restart around these exits. [Original issue and four updates](https://github.com/link-assistant/hive-mind/issues/4052)

## Source material

- [Attempt evidence](attempts.json) retains full execution and container identifiers, UTC durations, exit and memory evidence, reported log discrepancies, reviewed terminal lines and links to their sources. The earliest report for each UUID anchors the deduplicated timeline. The November 13 update repeated two rows, and the second November 20 update repeated seven with attachment links.
- [Artifact inventory](artifacts.json) records the downloaded issue body and comments, all 11 Gists, three restricted bot logs, an archived solver log and six historical CI jobs. File sizes, SHA-256 digests and newline counts refer to the retrieved bytes. Three large Gists returned incomplete preview content from `gh gist view` and were recovered by shallow Gist clones. The two Scala uploads have identical digests, as do the two Rust uploads.
- Source logs include account identifiers, tool transcripts and unrelated Telegram traffic. This public case study includes reviewed diagnostic lines and structured metadata. The inventory identifies the original artifacts for authorized retrieval. Several Docker-tail comparisons missed one to three lines of the stored wrapper log, so the report and linked target comments remain evidence in their own right. The code-quality solver archive ends during log upload, before the wrapper's final verdict.
- GitHub issue links identify the affected tasks. The issue has no listed sub-issues. The related checkout and Codex fixes are already merged. PR #4129 had no inline, conversation or review feedback at intake. [Pull request](https://github.com/link-assistant/hive-mind/pull/4129)

## Causes, responses and plans

### Reporter grouping and evidence loss

`signatureOf` in the Control Center handled known infrastructure and protocol signatures before falling back to the wrapper's broad reason. Ordinary exit 1 therefore grouped unrelated failures. The reporter's upper offset stopped a historical read at the next attempt, while its lower bound could still include an earlier attempt. A short resumed attempt could inherit the previous cause. [Original reporter](https://github.com/link-assistant/hive-mind-control-center/blob/9eab30b6f4c01868c0f068dc97628d4977159087/src/hive-control-center/auto-fix/report.mjs#L425-L483)

Hive Mind now classifies known solver terminal evidence through `tasks report --collect`, `--incident` and the optional `--group --by-signature`. It uses the existing half-open log intervals and bounded reads, returns only fixed signatures, keeps the existing metadata-only grouping available and preserves the fallback when the evidence is insufficient. For historical records with unknown attempt offsets, use the original isolated log or target failure comment for correlation. The [Control Center issue](https://github.com/link-assistant/hive-mind-control-center/issues/3) provides a two-record reproduction, a per-attempt workaround and proposed code to adopt the classifier and fix the Control Center's lower bound.

### Empty upstream and checkout normalization

The fork denial and failed first write were separate steps. The historical permission helper recommended forking even after GitHub rejected it and the generic comment suggested fork cleanup. Both solver paths now preserve the empty-repository reason and direct users to the first commit. When a maintainer supplies write access, direct initialization needs `--no-fork --auto-init-repository`. An owner can also add a README in GitHub and then rerun. The target repository now has a default branch. [Target discussion](https://github.com/veb86/ANCAD_SQLite/issues/1#issuecomment-7031878861)

The Java template tracked a CRLF blob while declaring a text checkout with CRLF working-tree line endings. Git stores normalized text with LF in the index. That mismatch can surface as a modification immediately after a clone. A maintainer can run `git add --renormalize -- mvnw.cmd` on a clean branch and review and commit the staged result. Hive Mind already has byte-checked local handling for checkout artifacts and an opt-in strict policy. The other three Java attempts show the same trigger and file. Only the issue 28 record supplies the index and worktree EOL values. The nearby global Git config mount warning had a successful fallback. [Existing Hive Mind fix](https://github.com/link-assistant/hive-mind/pull/4064) · [Java template report and repro](https://github.com/link-foundation/java-ai-driven-development-pipeline-template/issues/28) · [Git attributes reference](https://git-scm.com/docs/gitattributes)

### CI and verification stops

The Scala verifier used Scala CLI syntax with the legacy Scala 2.13 runner. It reached the `scala run Main.scala` line and tried to load a class named `run`. Run the compiled class as `scala -cp . Main` or install Scala CLI explicitly. The target issue proposes the exact patch to the verifier and identifies both failed jobs. [Scala CI report](https://github.com/konard/test-hello-world-019fb330-00e1-73b9-955e-f357a1600d5b/issues/3) · [Scala 2.13 runner](https://www.scala-lang.org/api/2.13.x/scala-compiler/scala/tools/nsc/MainGenericRunner.html)

The Rust run's `sh tests/verify-output.sh` returned `Hello, World!` and exit 0. Its next `git status --porcelain --untracked-files=all` also returned 0 and listed only the modified verification script and new workflow. Formal AI `0.355.27` then stopped before artifact inventory or commit. The planner uses the same refusal text for a rejected status receipt, unparseable porcelain and failures binding the issue or inventory plan, so the first failed predicate is unknown. Preserve the work and verify ownership of each path before a scoped commit and hosted CI run. The upstream report includes the transcript replay, workaround and branch-specific diagnostic proposal. [Formal AI report](https://github.com/link-assistant/formal-ai/issues/1628)

For Voice Simulator and Relative Meta Logic, fix the named project checks at the failing head and keep the acceptance thresholds. Failure of a check establishes the blocker without identifying the faulty application function. The linked target PRs already track those checks. Hive Mind's existing restart tracker records failing check names and URLs, and requires repeated matching output before stopping them early. Preserving these stops avoids spending the remaining budget on identical evidence. [Voice landmarks CI](https://github.com/konard/voice-simulator/actions/runs/44062832031/job/133970494190) · [Voice inversion CI](https://github.com/konard/voice-simulator/actions/runs/44396383296/job/135128173589) · [Relative Meta Logic automation stop](https://github.com/link-foundation/relative-meta-logic/pull/184#issuecomment-7049952766)

### Provider stops

For Code Quality, the tradeoff is to bound long turns and resume supported incomplete responses from the existing session, with bounded retries. That exact failure was fixed before this PR in #4080, including degenerate-output detection, token exhaustion recovery and restoration from a recovery branch. The Voice Simulator output-limit case has the same provider reason and does not establish the same degenerate stream. The policy stop exposes the provider category and no further reason. Keep it visible, preserve work, and treat remediation through the provider as separate from retrying a stalled session. [Existing Codex investigation and fixes](../issue-4079/README.md) · [Codex protocol report](https://github.com/openai/codex/issues/38831)

### Diagnostics and reusable components

When a generic execution exception recurs, rerun with `--verbose` to capture the solver phase and stack, alongside the corrected first-line error. Use the existing opt-in `--attach-logs` when it is appropriate to share a sanitized artifact. When the wrapper and Docker tails disagree, select the execution UUID and attempt, compare bounds and inspect the corresponding local log and task metadata. Docker events can corroborate a recent container lifecycle event. Its retained event window is limited, so an empty query long after exit only establishes that matching events were unavailable on that query. [Docker event reference](https://docs.docker.com/reference/cli/docker/system/events/)

Start-command already provides task IDs, offsets and per-attempt status. The existing manager reader safely bounds the file interval and the incident router already accepts a signature. A finite vocabulary follows OpenTelemetry guidance for low-cardinality error types and avoids a dependency, a metrics exporter or publication of raw provider messages. The existing checkout and Codex guard libraries already implement the applicable recovery. [Start-command tracking](https://github.com/link-foundation/start/blob/aad292e15790c030285bb3c9736728595e852164/README.md#execution-tracking) · [OpenTelemetry error conventions](https://opentelemetry.io/docs/specs/semconv/general/recording-errors/)
