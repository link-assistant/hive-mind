# Issue 2301: cancelled Claude background work and false recovery notice

Two `solve` runs ended the same way. In each, Claude Code's print mode (`claude -p`) stopped still-running background subagents, and Hive Mind reported the resulting synthetic "The user doesn't want to proceed with this tool use" as a user rejection, without resuming the work.

- **Incident 1:** [links-notation#315](https://github.com/link-foundation/links-notation/issues/315) → [PR #319](https://github.com/link-foundation/links-notation/pull/319). Claude Code 2.1.282, 2026-09-25, session `85671f31-4459-422e-8fef-04ee03fd3aa0`. It also had a container OOM event and a false "new session started" notice.
- **Incident 2:** [browser-commander](https://github.com/link-foundation/browser-commander) → [PR #106](https://github.com/link-foundation/browser-commander/pull/106). `solve` v2.33.1 with Claude Code 2.1.284, 2026-09-28, session `8e2c96c8-dd0a-4d8c-b438-bbebf1fd684b`. It ran for 2 h 32 min and cost $110.03.

## Exact root cause

Claude Code print mode does not end when the main thread goes idle. It waits for background tasks, but only up to a ceiling. The installed 2.1.284 binary contains `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS ?? 600000` and the kill switch `backgroundTasksDisabled || CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`. When the ceiling passes, print mode does four things:

1. It writes `Background tasks still running after 600s; terminating. Set CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0 to wait indefinitely.` to **stderr**.
2. It stops every task (`system/task_notification` with `status: "stopped"`), and counts subagents in `result.subagent_stats.killed.system`.
3. It gives each killed subagent a synthetic `[Request interrupted by user]` message and `The user doesn't want to proceed with this tool use…` tool results (`tool_use_result: "User rejected tool use"`). All of these events carry `parent_tool_use_id`.
4. It emits `result` with `subtype: "success"`, `terminal_reason: "completed"` and empty `permission_denials`, then exits with code 0.

No person, permission prompt or tool classifier is involved. `--dangerously-skip-permissions` was in effect in both runs. The "user rejection" is simply the text Claude Code uses for a cancelled tool call.

The model triggered this path by launching subagents with `run_in_background: true`. Incident 2 used worktree isolation for all 11 top-level agents. The model then ended its turn with a status message that it was waiting for them. A one-shot print run cannot deliver a later notification, so after 600 s the work was discarded.

### Live reproduction

[`experiments/issue-2301-print-bg-ceiling/repro-ceiling.sh`](../../../experiments/issue-2301-print-bg-ceiling/repro-ceiling.sh) reproduces the whole sequence in about a minute by lowering the ceiling to 8 s. The captures are in [`captured/`](../../../experiments/issue-2301-print-bg-ceiling/captured):

- **Background Agent:** the stderr ceiling line appears, then `stopped`, `killed.system=1`, and a synthetic `[Request interrupted by user]` / `User rejected tool use` inside the subagent.
- **Background Bash:** no wait and no stderr line. The task is `stopped` about 4 s after `result`, and **`killed.system` stays 0**. Detection based on `killed.system` alone therefore misses it.
- **Fixed env** (`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`, `CLAUDE_CODE_DISABLE_WORKFLOWS=1`, `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1`): the model still asks for `run_in_background: true`, but the agent runs in the foreground and `completed`. The result has `started_in_background=0` and contains the agent's answer.

## Requirements and root causes

1. **Finish authorized work without a false user-feedback request.** The text came from Claude Code's ceiling sweep of background subagents, not from a Hive Mind tool classifier or a real user. `--no-tool-check` skips only Hive Mind's connection checks, and `permission_denials` was empty. Codex was not used in either incident; its noninteractive runner already uses `--dangerously-bypass-approvals-and-sandbox`, and there is no evidence of a Codex classifier failure.
2. **Actually finish pending Claude work.** Keep one-shot work in the foreground, detect a cancelled turn exactly, and make one bounded same-session continuation. If that attempt also ends incomplete, report a real failure instead of declaring the issue solved. Streaming-input sessions keep their long-running behavior.
3. **Resume after an OOM event followed by exit 1.** Docker's `OOMKilled` flag can coexist with a surviving main process. The monitor now keeps the OOM observation for an ordinary exit, classifies exit 1 plus OOM as a failed run affected by a child OOM, and runs the bounded `--on-session-kill=resume` path.
4. **Report what actually happened.** The OOM notice now separates survived, failed-after-OOM and actually restarted. It claims a new session only after the launch succeeds, and includes the session's ID.
5. **Keep experiments from starving concurrent work.** Each Docker Telegram task defaults to a 25% host-memory limit (`--container-memory` / `TELEGRAM_CONTAINER_MEMORY`), and the prompts ask for bounded experiments ([Docker resource constraints](https://docs.docker.com/engine/containers/resource_constraints/)).
6. **Preserve and study the evidence.** This directory holds the logs, the replay fixtures under `tests/fixtures/issue-2301/`, and the experiments under `experiments/issue-2301-print-bg-ceiling/`.

## Upstream and existing solutions

- Claude Code's [environment-variable documentation](https://code.claude.com/docs/en/env-vars) describes `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`. The ceiling variable is named only in the stderr message.
- [anthropics/claude-code#85066](https://github.com/anthropics/claude-code/issues/85066) reports a silent success with orphaned subagents. [This follow-up](https://github.com/anthropics/claude-code/issues/85066#issuecomment-5842704259) gives the reproduction, workaround and suggested fixes, and a [second follow-up](https://github.com/anthropics/claude-code/issues/85066#issuecomment-5885429221) adds the exact ceiling mechanism, the misleading "User rejected tool use" text under `bypassPermissions`, and the bash kill with `killed.system=0`.
- [#89495](https://github.com/anthropics/claude-code/issues/89495) has a small `claude -p` Bash reproduction confirming the env workaround. [#82235](https://github.com/anthropics/claude-code/issues/82235) describes a related post-turn task-notification error.
- Suggested upstream fixes:
  - Emit `result` with a non-success subtype, or a `terminal_reason` such as `background_tasks_terminated`, when the sweep cancels work.
  - Use a cancellation message that does not mention a user.
  - Count local_bash tasks in `subagent_stats`.
  - Reject or foreground `run_in_background` in one-shot print mode.
- No library consumes Claude stream-json with these semantics. The official [Agent SDK](https://docs.claude.com/en/docs/agent-sdk/overview) exposes the same events, so the tracker is implemented locally. Keeping stream-json input open (`--input-format stream-json`) would also avoid the ceiling, but it changes the runner's session lifecycle much more than the bounded continuation.
