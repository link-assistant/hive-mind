## Additional request: configurable lock modes

The issue that uses this store (link-assistant/hive-mind#4143) also needs the lock to be tied to the owning process, so that a dead process never blocks the store, with the lock strategy configurable. `FileLock` in `rust/src/storage/lock.rs` already covers the first part, since `flock`/`LockFileEx` is released by the OS when the process exits. Suggested CLI surface:

| Option                   | Behaviour                                                                                                                                                                                                                                                                                           |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--lock flock` (default) | `FileLock` on `<db>.lock`: exclusive for writes, shared for `--out`. The OS releases it when the process exits.                                                                                                                                                                                     |
| `--lock pid`             | Creates `<db>.lock.d` with `O_EXCL`/`mkdir` and an owner file (`pid`, `hostname`, PID namespace, start time). A waiter breaks the lock when the owner is on the same host and its PID is gone. This covers file systems where `flock` is not reliable (some NFS and bind mounts across containers). |
| `--lock none`            | No locking, for callers that serialize access themselves.                                                                                                                                                                                                                                           |
| `--lock-timeout <ms>`    | How long to wait. On timeout, exit non-zero with the current owner in the message.                                                                                                                                                                                                                  |

This matches the external lock hive-mind uses as a workaround (`src/state-lock.lib.mjs` in link-assistant/hive-mind#4143). That lock has `pid`, `age` and `none` modes, selected by `HIVE_MIND_STATE_LOCK_MODE`. A `clink --lock-status` (or `--verbose` output naming the lock holder) would also help operators diagnose a stuck writer.
