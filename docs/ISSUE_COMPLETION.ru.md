# Проверка выполнения задачи перед автоматическим слиянием

При решении задачи solve теперь восстанавливает описание пул-реквеста после каждой рабочей сессии и проверяет выполнение даже без `--finalize` или `--ensure-all-sub-issues-addressed`. Исходная задача, вложенные подзадачи GitHub и обязательные ссылки в теле общей задачи должны иметь утвердительные закрывающие ссылки в описании. Ссылки в примерах, комментариях, заголовках или отрицательных предложениях не подтверждают связь. Для задач другого репозитория нужно указать точный репозиторий.

В режиме репозитория тело общей задачи содержит все открытые задачи. GitHub допускает лишь 100 непосредственных подзадач; остальные остаются в обязательном списке ссылок и входят в объём того же пул-реквеста.

Промпты всех шести инструментов требуют полной реализации и проверки в этом пул-реквесте. Codex запускается с `features.goals=true`; промпты предлагают задать цель через поддерживаемый встроенный API, а при его отсутствии сохранять постоянный план и список проверок. Цикл завершения по умолчанию допускает пять перезапусков; `--ensure-all-sub-issues-addressed=N` также задаёт этот предел. Исчерпание попыток, лимит использования или недоступные данные GitHub оставляют пул-реквест неслитым.

## Создание отчёта о требованиях

После последней отправки коммитов создайте шаблон из актуальных описаний задач, всех комментариев к задачам и трёх типов обратной связи пул-реквеста:

```bash
node /path/to/hive-mind/src/issue-requirements-snapshot.mjs OWNER/REPO ISSUE_NUMBER PR_NUMBER
```

Промпты инструментов предоставляют абсолютный путь установленного скрипта. Команда только читает GitHub и выводит шаблон; начальный статус каждого пункта — `pending`. Добавьте текстовые требования, которые извлечение явных списков не распознало. Для каждого требования укажите проверяемые доказательства реализации и проверки; ставьте `done` только после выполнения. Нерешённые требования оставляйте как `blocked`. Вставьте весь отчёт вместе с его маркерами в описание пул-реквеста:

```text
<!-- hive-mind:requirements:start -->
...сформированный JSON-отчёт...
<!-- hive-mind:requirements:end -->
```

После нового коммита или изменений требований и отзывов сформируйте отчёт заново. Сохраняйте его при редактировании описания. Закрывающие ссылки должны находиться вне блока кода отчёта; повторяйте утвердительное закрывающее слово отдельно для каждой задачи.

## Условия разрешения слияния

Общая функция слияния проверяет все автоматические пути, включая очередь, и требует:

- Утвердительные закрывающие ссылки для полного обязательного набора задач.
- Ровно один корректный отчёт, охватывающий именно этот набор.
- Текущий SHA головного коммита и актуальные хеши источников требований.
- Все явные критерии приёмки, статусы `done` и непустые доказательства.
- При целевой ветке по умолчанию — подтверждённые GitHub закрывающие связи.

Чтение GitHub, пагинация и проверка ответов должны завершиться успешно. Команда слияния также использует `--match-head-commit`, чтобы отклонить одновременную отправку кода. При слиянии в другую ветку GitHub не закрывает задачи автоматически; hive-mind закрывает каждую проверенную задачу после слияния и сообщает об отдельных ошибках. Обслуживание только пул-реквеста без контекста задачи продолжает использовать существующий процесс.

Подробный режим записывает число проверенных задач и SHA; ошибки проверки указывают причину блокировки. Комментарии о блокировке требуют завершить работу и предоставить доказательства, а не рекомендуют ручное слияние.

## Ограничения проверки

Отчёт — обязательная актуальная опись доказательств, а не доказательство выполнения произвольного текста или правдивости утверждений агента. Люди должны проверять эти сведения. Администратор репозитория может выполнить слияние вне hive-mind; комментарии и описание могут измениться между последним чтением и слиянием. GitHub защищает коммит, но не предоставляет атомарную блокировку всех внешних записей. Большие списки также ограничены размером тела и лимитами API GitHub; ошибки публикации или проверки должны блокировать слияние.

[Исследование задачи 2335](case-studies/issue-2335/README.md) описывает воспроизведённую ошибку, реализацию, тесты и эти практические ограничения.
