# Case study: issue #2563: auto-merge held back on a linked pull request, and the same log attached twice

- Issue: https://github.com/link-assistant/hive-mind/issues/2563
- Pull request with the fix: https://github.com/link-assistant/hive-mind/pull/2566
- Affected run: [link-foundation/command-stream#206](https://github.com/link-foundation/command-stream/pull/206), `solve v2.33.11 https://github.com/link-foundation/command-stream/pull/206 --think xhigh --auto-merge --tool codex --attach-logs --verbose`

## Summary

The description of command-stream#206 begins with "Fixes #205. Unblocks [link-assistant/agent#320](https://github.com/link-assistant/agent/issues/320)", and GitHub links the pull request to #205 (`closingIssuesReferences`). The pull request was created while solving link-assistant/agent#320, so its branch is `issue-320-b2913f5b1c99`. Three comments followed the work session:

| #   | Root cause                                                                                                                                                                                                                                                                                                                                                             | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RC1 | For a pull request URL, solve took the issue number from the branch name first (`issue-320-…` → #320) and used the description only when the branch had none (log line 84: `🔗 Found linked issue #320`). command-stream#320 does not exist, so every pre-merge gate failed with HTTP 404 and held the merge back, although CI passed and the description closed #205. | `resolvePullRequestIssueNumber` (`src/github-linking.lib.mjs`) keeps the branch number as a hint. The description's same-repository closing reference wins when the description names the branch number only in **another** repository (`link-assistant/agent#320`), or when GitHub reports the branch issue missing (404/410) or as a pull request. The recovery of a deleted `Fixes #N` from #2335 is unchanged, because an existing branch issue still wins.                             |
| RC2 | `attachLogAfterAutoMergeBlocked` (added in #2395 as RC4) uploaded the log again on every held-back merge. Here the auto-merge loop ran **no** AI session after the first upload: it waited for CI (14:43:46 to 14:46:23) and held the merge back. The second log is the first log plus 152 lines of that wait.                                                         | Every finished AI session is counted in `classifySessionResult`, which runs after each session for every tool, and compared with the count at the latest successful upload (`src/log-attach-state.lib.mjs`). A held-back merge uploads nothing when the attached log already covers every AI session; the auto-merge blocked comment explains the stop. When AI work is not attached yet, the auto-merge blocked notice leads that log comment (`leadingSection`), so both are one comment. |
| RC3 | The re-upload passed only `sessionId`, `argv`, `requestedModel` and `tool` to `attachLogToGitHub`, so `buildCostInfoString` and `buildBudgetStatsString` had no data and only "🤖 Models used" was rendered. Each of the many `attachLogToGitHub` call sites decided on its own which usage data to pass.                                                              | `attachLogToGitHub` remembers the usage data (`publicPricingEstimate`, `pricingInfo`, `anthropicTotalCostUSD`, `resultModelUsage`, `budgetStatsData`) of every finished session and every upload, and fills the missing fields of any upload with it. All tools and all call sites render cost estimation, context and tokens usage and models used from one place.                                                                                                                         |

Trade-off: in #2395 the re-upload also published the non-AI tail of the log (the CI wait). Without new AI work that tail is no longer uploaded, because the auto-merge blocked comment already states the reason for the stop.

## Reproduction and tests

- `node experiments/issue-2563/reproduce-branch-issue.mjs` prints the issue number solve chooses for command-stream#206 (#205 after the fix, #320 before it).
- `tests/issue-2563-primary-issue-resolution.test.mjs` (RC1) runs `resolveSolveMode` and `checkIssueLinksBeforeMerge` against a fake GitHub that answers like the real one did (#205 exists, #320 returns 404).
- `tests/issue-2563-log-after-held-back-merge.test.mjs` (RC2, RC3) replays the run: the held-back merge without new AI work does not upload again. AI work that is not attached yet is uploaded together with the notice in one comment. The real `attachLogToGitHub` renders all three sections for an upload that carries no usage data. Without the fix, the replay fails because the log is uploaded a second time, and the format test fails with `### 💰 **Cost estimation:** missing`.
