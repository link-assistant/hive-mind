# Telegram command routing across Hive Mind bots

## Observed behavior

Two bot accounts with group privacy mode disabled or with administrator rights can receive the same bare command. Hive Mind registers some commands directly in `telegram-bot.mjs` and others in command modules. Telegraf matches the first command entity. For a subset of commands, including its solve aliases, the bot also attempts text matching if entity-based dispatch skipped the update.

Both dispatch paths already check the username when one is supplied. Neither path checked whether a peer Hive Mind bot could also respond to a bare command. For work commands this could lead to two independent launches. For read-only commands it could lead to duplicate help, version, or resource-limit replies.

The code paths and command grammar were checked against the work that added solve batches, dependency aliases, and recovery for invisible separators. The repository setup already calls for granting the bot administrator status. A public repository trace records the official bot's Telegram profile as `SwarmMindBot` with display name `Hive Mind`. [Batch solutions PR](https://github.com/link-assistant/hive-mind/pull/4068) · [Dependency aliases PR](https://github.com/link-assistant/hive-mind/pull/4070) · [Command grammar PR](https://github.com/link-assistant/hive-mind/pull/2252) · [Published profile trace](../issue-1722/data/hive-telegram-bot.txt)

Run `node --test --test-concurrency=1 tests/telegram-command-routing-4101.test.mjs tests/telegram-peer-discovery-4101.test.mjs`. The simulated polling path sends a bare `/help` to an upgraded bot with an existing ordinary peer. Before active discovery, the first reply was the help text. A second test simulates both ordinary bots receiving their first bare work command together, exchanging identities, and allowing only the addressed launch.

For a live check, use two upgraded Hive Mind accounts with custom usernames in a Telegram test group. Enable Bot-to-Bot Communication Mode on both and disable Group Privacy Mode for ordinary members that should receive bare probes. Send `/version`, `/help` and `/limits`. Expect identity traffic during discovery and silence for the bare commands once both peers are confirmed. Send `/version@FirstBot` and `/who@SecondBot` and verify that only the addressed bot answers each. Remove the second bot and send `/version` again to verify that bare access resumes. This procedure requires the two accounts and a Telegram test group.

The entry-point test also ran against the original `telegram-bot.mjs`. It failed because the bot sent a reply to the bare `/help` and entered the text fallback for the bare `/do`. With routing middleware installed, only the addressed inputs produced replies.

## Platform evidence

- Telegram documents `/command@OtherBot` addressing. It delivers service messages to bots independently of ordinary privacy filters. Privacy mode affects who receives bare commands. Administrator bots and bots with privacy disabled may both receive one update. [Telegram Bot Features](https://core.telegram.org/bots/features#commands) · [Telegram Bot FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get)
- The HTTP Bot API can return bot administrators using `getChatAdministrators` and `return_bots: true`. It can look up individual IDs via `getChatMember`, which Telegram only guarantees for other users when the observer is a chat administrator. It exposes a count, without a complete member listing. `chat_member` needs administrator rights and an explicit update subscription. Join and leave service messages provide additional observations. [Bot API changelog](https://core.telegram.org/bots/api-changelog) · [Administrator list](https://core.telegram.org/bots/api#getchatadministrators) · [Known member lookup](https://core.telegram.org/bots/api#getchatmember) · [Updates](https://core.telegram.org/bots/api#update)
- A Telegram user record gives a bot's numeric ID, display name, and username. These are the available inputs for recognizing the project convention. Bot owners can customize the names, so a configured numeric ID is stronger evidence for a deployment. [Telegram User fields](https://core.telegram.org/bots/api#user)
- In groups, a targeted bot command or a direct reply can reach the target when either bot has Bot-to-Bot Communication Mode enabled. A recipient with that mode enabled also receives unaddressed bot messages when it is a group administrator or has Group Privacy Mode disabled. Telegram supplies the author ID and the original message for replies in the same chat and thread. Older `/version` handlers edit the initial progress message, so discovery subscribes to edited messages. [Telegram Message fields](https://core.telegram.org/bots/api#message) · [Telegram bot-to-bot delivery](https://core.telegram.org/api/bots/bot-to-bot) · [Legacy report source](https://github.com/link-assistant/hive-mind/blob/v2.39.10/src/telegram-bot.mjs)
- The initial version command reported the same package version on three lines for `Bot`, `solve`, and `hive`. Later releases added a `Bot Components` heading and bullets before consolidating the fields into a `Hive-Mind` package block in 1.23.14. [First version report](https://github.com/link-assistant/hive-mind/blob/v0.44.0/src/version-info.lib.mjs) · [Component report](https://github.com/link-assistant/hive-mind/blob/v1.23.13/src/version-info.lib.mjs) · [Consolidated report](https://github.com/link-assistant/hive-mind/blob/v1.23.14/src/version-info.lib.mjs)
- Telegraf's command handler checks the addressed username using the command entity. Its `callApi` accepts an abort signal and arbitrary method parameters, so Hive Mind can pass `return_bots` using its existing instrumented client. [Telegraf composer](https://github.com/telegraf/telegraf/blob/v4.16.3/src/composer.ts) · [Telegraf API client](https://github.com/telegraf/telegraf/blob/v4.16.3/src/core/network/client.ts)

## Solution options and plan

1. Reuse the shipped command-prefix parser and install a single middleware before command handlers. Check address matches there so entity handlers and the text fallback cannot independently admit a bare command. Telegram privacy mode alone depends on chat and bot settings and cannot enforce the choice to ignore a bare command everywhere.
2. Use the current Bot API as the discovery source for the supported deployment. The administrator list handles existing branded administrator bots. Service messages, subscribed membership updates, and visible group authors add ordinary peers over time. Persist the observed IDs in the existing bot state directory, under the receiving bot's numeric ID. Recheck presence on bare commands, bound API calls on the polling path, coalesce overlapping reads, and suppress dispatch if membership changes during a lookup. Explicit commands require no discovery call.
3. Support per-group numeric IDs for separately named or pre-existing peers. This uses the same routing rule and verifies current membership rather than permanently requiring an address after a peer departs. Apply the same routing code to every participating Hive Mind bot.
4. The grammY chat-members plugin implements event-backed storage and corroborates the absence of an HTTP Bot API membership listing. Moving to another Bot API framework would leave the initial discovery gap. Telegram's MTProto methods can return participant information for basic groups and offer participant filters for supergroups. Bot authorization over MTProto requires an application ID and hash in addition to the bot token, and supergroup queries can require administrator permissions. A roster would still need a product identity for arbitrary profiles. [grammY chat-members](https://grammy.dev/plugins/chat-members) · [MTProto bot authorization](https://core.telegram.org/method/auth.importBotAuthorization) · [Basic group query](https://core.telegram.org/method/messages.getFullChat) · [Supergroup participant query](https://core.telegram.org/method/channels.getParticipants)
5. When Telegram exposes an unfamiliar bot, probe it by username with `/who` and then `/version` if needed. Where the administrator list and member count leave room for an unseen bot, also allow a silent `/who` probe with no target. Use Telegram's reply relationship, author, and message IDs to associate answers with requests. Those fields prove which account answered. Bot owners control their reply text, so the reported product is an identity claim. The timing and reply limits implement Telegram's loop prevention guidance. [Telegram bot-to-bot delivery](https://core.telegram.org/api/bots/bot-to-bot)
6. Keep the initial wait outside the polling path. Polling awaits each batch before reading the next batch, which may contain the identity answer. A bounded wait lets Telegram deliver the answer while explicitly addressed commands and unrelated chats proceed. Legacy answers that arrive after the wait can still inform subsequent routing. [Telegraf polling implementation](https://github.com/telegraf/telegraf/blob/v4.16.3/src/core/network/polling.ts)
7. A central roster would need to know every installation and its group memberships before accepting the first command. MTProto can look up participant lists in more cases, including with the repository's `teleproto` dependency, but it requires API application credentials and can require privileges. A list of ids would still need a way to identify unrelatedly named peers. [Basic group query](https://core.telegram.org/method/messages.getFullChat) · [Supergroup participant query](https://core.telegram.org/method/channels.getParticipants)

## Open criterion

Automatic discovery of every pre-existing ordinary bot remains blocked when its identity is hidden and Telegram suppresses the unaddressed `/who`. A human and a hidden bot can occupy the same ordinary membership slot in otherwise identical chats. Telegram can return the same administrators, member count, input command and absence of replies in both chats. The application then permits bare commands to preserve solo behavior, so duplicate dispatch remains possible. A delivered `/who` response, a branded administrator, a membership event, or a configured ID provides the missing observation. A legacy process can reveal its identity with `/version`, but it continues executing its own bare commands until it is upgraded. The tests exercise simulated Telegram delivery. Live delivery verification requires actual bot accounts and a test group.
