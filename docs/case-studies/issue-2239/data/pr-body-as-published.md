## Summary

Implements `GraphVisualization.svelte` (issue #1) on top of the current upstream structure
(Feature-Sliced layout, Yarn 4, Svelte 5 runes). The branch also merges `upstream/main`, which had
diverged heavily since the first draft, so the component was re-authored rather than patched.

- **Views**: force-directed (default), Sankey and vis-network, switchable at runtime from the
  toolbar or via the bindable `visualizationType` prop.
- **Interaction**: zoom/pan, node dragging, hover tooltips for nodes and edges, click callbacks,
  hierarchical collapse/expand of subgraphs (double-click a node or `toggleCollapse(id)`).
- **Styling**: per-node, per-type and global colour/size/shape overrides, node and edge labels,
  and a legend built from the visible data. Styles use the design-system custom properties from
  `src/app.css`; a `@media (max-width: 640px)` rule keeps the toolbar usable on phones.
- **Export**: `exportToPNG()` / `exportToSVG()` accept a filename or `ExportOptions`
  (`filename`, `width`, `height`, `scale`), so resolution is configurable. The SVG path reuses the
  existing `$lib/utils/export` helpers.
- **SSR safe**: `d3`, `d3-sankey` and `vis-network` are loaded with dynamic `import()` inside
  `onMount`; a `ResizeObserver` keeps the layout responsive.
- **Performance**: above 500 nodes the force layout is ticked synchronously and vis-network physics
  is disabled; a 1000-node dataset is covered by a test and by the demo page.

## Bugs found and fixed while testing

- **Tooltips never appeared.** The `$effect` that re-renders the graph read `tooltip.visible`
  transitively (`render() → teardown() → hideTooltip()`), so the first hover re-triggered the effect
  and hid the tooltip again. `render()` now runs inside `untrack()`. Reproduced by the browser test
  `shows a tooltip on node hover and hides it again`, which failed before the fix.
- **Oversized edges in the network view.** vis-network used the edge/node `value` field to rescale
  elements, overriding the resolved styles (visible as a giant "has child" edge). `value` is no
  longer forwarded to vis-network.

## Pre-existing repository issues noticed (not fixed here)

- `vite.config.ts` used `environment: 'browser'` and `provider: 'playwright'`, both rejected by
  vitest 4, so **no** unit test could run. Fixed in this PR (`browser.enabled` + the
  `@vitest/browser-playwright` provider factory) because it was blocking.
- CI workflows run in `working-directory: packages/frontend`, which does not exist in this repo.
- `package.json` has no `packageManager` field, so `corepack enable && yarn install --immutable`
  resolves Yarn 1 and fails on the `portal:../stylist-svelte` dependency.
- CI uses Node 20, where Houdini fails with `ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite` (needs 22+).
- `src/lib/index.ts` still re-exports `./components/ui` and `./stores/online.store`, which no longer
  exist.
