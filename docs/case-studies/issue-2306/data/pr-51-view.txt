## Exact-source release and provenance

The release workflow previously created a version commit and published from the **old** workflow SHA. npm builds its provenance statement from `GITHUB_SHA`, so that sequence could not attest the tested version commit. Automatic and instant versioning now dispatch a fresh `release.yml` run pinned to the new commit. That run checks its SHA and checkout, reruns Node/Bun/Deno quality gates, publishes with provenance, and sends the one published version through Docker and release-identity assembly.

The clean registry smoke test installs with a lockfile, uses `npm audit signatures --json --include-attestations`, and extracts the npm-verified source repository and commit for the exact package version. Release identity rejects a source mismatch against the tested commit, repository, or registry predicate. Tests reproduce mismatched sources, and a real public `@mtcute/node@0.32.2` audit passed. This project package remains unpublished, so its own provenance and immutable identity still require the owner-supplied first-publish token.
