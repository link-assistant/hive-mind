## GitHub platform

### G1 — Issues and Projects

Issues hold the shared text, assignees, labels, milestones, links, dependencies and sub-issues. The documented maximum is 100 direct sub-issues and eight levels of nesting. Use the native relations and paginate reads. Project views provide table, board and roadmap formats and custom fields for work such as dates and status. The GraphQL API exposes Projects v2. Confirm the installation/user access and grants for each supported owner before making a Projects field a routing requirement. Use a documented label rule where no Project is configured. [Issue creation and templates](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue) · [Dependencies](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-issue-dependencies) · [Sub-issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/adding-sub-issues) · [Projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects) · [Projects API](https://docs.github.com/en/issues/planning-and-tracking-with-projects/automating-your-project/using-the-api-to-manage-projects)

### G2 — Actions and webhooks

Actions can provide repository-owned manual and scheduled admission and its normal run logs. Scheduled workflows run on the default branch, have a minimum five-minute interval, and can be delayed or dropped under load. A self-hosted runner or a local service can handle workloads that need environment affinity. Keep occurrence bookkeeping in the execution service where missed schedules and repeats can be reconciled. For GitHub App webhooks, check the delivery signature, scope actions to specific installations and repositories, return a timely acknowledgment, and process from durable storage. Redeliveries retain the delivery ID. Keep polling as a reconciliation path. [Actions schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) · [Workflow logs](https://docs.github.com/en/actions/how-tos/monitor-workflows/use-workflow-run-logs) · [Self-hosted runners](https://docs.github.com/en/actions/concepts/runners/self-hosted-runners) · [Webhook practices](https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks)

### G3 — Pull requests, checks, and merge policy

Pull requests already provide files, diffs and review. A GitHub App with Checks write permissions can attach a compact, head-specific result to an existing review. Preserve native review and ruleset enforcement. Re-read the pull request head before taking action on delayed or cached status. Repositories using merge queue need the appropriate `merge_group` trigger to report required checks on the queue's commit. Keep detailed CI logs within their native permission boundary and link to them from safe summaries. [Checks API](https://docs.github.com/en/rest/checks) · [Check runs](https://docs.github.com/en/rest/checks/runs) · [Rulesets](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets) · [Merge queue](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue) · [Workflow logs](https://docs.github.com/en/actions/how-tos/monitor-workflows/use-workflow-run-logs)

### G4 — Mobile, notifications, and agent baseline

GitHub supports subscriptions and inbox notifications plus a mobile client for issue and PR collaboration. These are the default portable surfaces for review and team work. A Hive Mind session can need separate execution controls or a time-sensitive answer. Continue those through an authorized channel with a link to the related GitHub record and deduplicate by transition. Include GitHub's own agent workflow as an alternative in the benchmark. [GitHub notifications](https://docs.github.com/en/subscriptions-and-notifications/concepts/about-notifications) · [GitHub Mobile](https://docs.github.com/en/get-started/using-github/github-mobile) · [GitHub Copilot on GitHub](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-on-github) · [Telegram Bot API](https://core.telegram.org/bots/api)
