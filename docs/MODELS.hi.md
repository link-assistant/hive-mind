# मॉडल: लाइव कैटलॉग, `/models` और `hive-models` (languages: [en](MODELS.md) • [zh](MODELS.zh.md) • hi • [ru](MODELS.ru.md))

किसी प्रदाता ने आज सुबह जो मॉडल जारी किया, वह आपके किसी काम का नहीं यदि Hive Mind
को केवल वही सूची पता हो जिसके साथ वह प्रकाशित हुआ था। यह पृष्ठ बताता है कि Hive
Mind **अभी इस समय** मौजूद मॉडलों का पता कैसे लगाता है, उनसे कैसे पूछें, और वह एक
नियम जिसके चारों ओर पूरी व्यवस्था बनी है: **मॉडलों की सूची लेना आपके टोकन कभी खर्च
नहीं करना चाहिए।**

> **⚠️ प्रयोगात्मक।** लाइव स्रोत नए हैं (issue
> [#2202](https://github.com/link-assistant/hive-mind/issues/2202))। अंतर्निहित
> कैटलॉग नया नहीं है: यह वही सूची है जिसके विरुद्ध Hive Mind हमेशा से `--model`
> की जाँच करता आया है, और जब कोई भी लाइव स्रोत उपलब्ध न हो तो उत्तर वही रहता है।
> यहाँ कुछ भी किसी run को विफल नहीं कर सकता — जो स्रोत विफल होता है, उसे दर्ज
> करके छोड़ दिया जाता है।

## पूछें कि क्या उपलब्ध है

```bash
# सभी tools, कैश किए गए उत्तरों के साथ।
hive-models

# केवल Codex।
hive-models --tool codex

# Claude, context window, मूल्य और स्रोत सहित, कैश को अनदेखा करते हुए।
hive-models --tool claude --details --refresh

# मशीन-पठनीय आउटपुट।
hive-models --json | jq '.tools.claude.liveOnly'
```

Telegram में यही सूची `/models` है, और वह वही विकल्प उदार रूप में स्वीकार करती है —
`/models --tool codex`, `/models --tool=codex` और `/models codex` का एक ही अर्थ है,
क्योंकि chat कोई shell नहीं है:

```
/models
/models codex --details
/models --all
```

बिना विकल्प के `/models` `claude` के बारे में उत्तर देता है; `--all` हर tool के लिए
एक अलग संदेश भेजता है।

## उत्तर कैसे पढ़ें

```
Models for claude (default: opus)
3 bundled and live · 2 hot loaded · 14 bundled only

Bundled and live (3) — shipped with this installation and confirmed reachable now
  * claude-opus-5 (opus, opus-5) [1M ctx · 128K out · $5/$25 per Mtok · reasoning · text+image+pdf · 2026-07-24]
    claude-sonnet-5 (sonnet, sonnet-5)
    ...

Hot loaded (2) — a live source has them, this installation does not ship them
    claude-fable-5-2
    ...

Bundled only (14) — shipped, but no live source confirmed them
    ...

Sources, in the order they are trusted:
  - Link.Assistant Router: ok — 41 model(s)
  - Anthropic GET /v1/models: skipped — ANTHROPIC_API_KEY is not set
  - models.dev: ok — specifications for 3570 model(s)
  - Bundled with this installation: ok — 17 model(s)

Live answers are cached for 1h 0m; pass --refresh to ignore the cache.
```

ये तीन समूह ही इस command का मुख्य उद्देश्य हैं:

| समूह                 | अर्थ                                                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Bundled and live** | यहाँ शामिल है **और** किसी लाइव स्रोत ने पुष्टि की है। निश्चिंत होकर उपयोग करें।                                                         |
| **Hot loaded**       | किसी लाइव स्रोत के पास है, पर इस installation के साथ नहीं आता। अभी उपयोग योग्य है।                                                      |
| **Bundled only**     | यहाँ शामिल है, पर किसी लाइव स्रोत ने पुष्टि नहीं की — हटा दिया गया, नाम बदल गया, या आपके खाते को अधिकार नहीं है। फिर भी काम कर सकता है। |

`*` उस tool के डिफ़ॉल्ट model को चिह्नित करता है। कोष्ठक में दिए नाम वे उपनाम हैं
जिन्हें `--model` में दिया जा सकता है। `--details` विनिर्देश और हर model के स्रोत
भी दिखाता है।

जब `HIVE_MIND_MODELS_HOT_LOAD=0` हो, तो तीसरे समूह का शीर्षक केवल **Bundled** होता
है — जब किसी लाइव स्रोत से पूछा ही नहीं गया, तो उन्हें "अपुष्ट" कहना ऐसा आरोप होगा
जिसे command सिद्ध नहीं कर सकती।

## सूची कहाँ से आती है

स्रोतों को इसी क्रम में आज़माया जाता है, और यही क्रम प्राथमिकता भी तय करता है जब दो
स्रोत एक ही model का वर्णन करें:

| #   | स्रोत                        | क्या देता है | इसी स्थान पर भरोसा क्यों                                                                                                              |
| --- | ---------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Link.Assistant Router        | उपलब्धता     | वह gateway जिससे routed कार्य वास्तव में बात करता है। केवल यही बता सकता है कि model _उसी रास्ते पर_ पहुँच योग्य है जिससे कार्य जाएगा। |
| 2   | `codex debug models`         | उपलब्धता     | स्थापित Codex binary अपने ही कैटलॉग से उत्तर देता है — कोई नेटवर्क अनुरोध नहीं, और वह क्या स्वीकारेगा इस पर सबसे प्रामाणिक।           |
| 3   | Anthropic `GET /v1/models`   | उपलब्धता     | इस API key को जिन models का अधिकार है।                                                                                                |
| 4   | OpenAI `GET /v1/models`      | उपलब्धता     | वही रूप, वही तर्क।                                                                                                                    |
| 5   | models.dev                   | मेटाडेटा     | Context window, मूल्य, modality, रिलीज़ तिथि। यह उपलब्ध सूची में model **कभी** नहीं जोड़ता — केवल टिप्पणी करता है।                    |
| 6   | इस installation के साथ शामिल | उपलब्धता     | `src/models/catalog.mjs`. हमेशा मौजूद; जब बाकी सब अनुपलब्ध हो तब यही उत्तर है।                                                        |

Router स्रोत से केवल तभी पूछा जाता है जब router पहले से पहुँच योग्य हो या स्थानीय
रूप से शुरू किया जा सके; operator द्वारा चलाया गया router (`HIVE_MIND_ROUTER_URL`)
उपयोग तो होता है, पर यह command उसे कभी शुरू या बंद नहीं करती। देखें
[Router आइसोलेशन](./ROUTER.hi.md)।

## मॉडल सूचीबद्ध करना कभी टोकन खर्च नहीं करता

Issue #2202 इसे कठोर शर्त के रूप में रखता है: _"मॉडल निष्कर्षण से कभी कोई टोकन व्यय
नहीं होना चाहिए, अन्यथा ऐसी विधियाँ हमारे codebase से हटा दी जानी चाहिए।"_ यह
**स्रोतों** का गुण है, इसलिए इसे वहीं लागू किया जाता है जहाँ स्रोत घोषित होता है, न
कि हर call site पर भरोसे से (`src/model-catalogue-sources.lib.mjs`)। दो अतिरिक्त
सुरक्षा-परतें:

1. **`assertTokenFreeSource`** ऐसे किसी भी स्रोत को अस्वीकार करता है जिसने स्पष्ट
   रूप से `billable: false` घोषित न किया हो। कोई स्रोत चूक से शुल्क-योग्य नहीं बन
   सकता।
2. **`assertTokenFreeUrl`** ऐसे हर URL को अस्वीकार करता है जिसका path completion
   endpoint हो, चाहे वह किसी भी descriptor के साथ आया हो। `/v1/models` को
   `/v1/messages` बना देने वाली टाइपिंग-त्रुटि खर्च करने के बजाय exception फेंकती है।

नियम का दूसरा आधा भाग यह अभिलेख है कि क्या लागू **नहीं** किया गया, ताकि "हम ऐसा
नहीं करते" केवल अनुपस्थिति न रहकर समीक्षा-योग्य कथन बने:

| अस्वीकृत विधि                                           | कारण                                                                                                                                                             |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claude Code TUI का `/model` picker चलाना                | TUI शुरू करना ही session शुरू कर देता है, और Claude Code session प्रारंभ पर अनुरोध भेजता है। यह खर्च वास्तविक और अदृश्य है, और किसी और के बिल पर आता है।         |
| Codex TUI का `/model` picker चलाना                      | `codex debug models` वही कैटलॉग JSON में बिना किसी नेटवर्क कॉल के देता है, इसलिए TUI केवल लागत और अस्थिरता जोड़ता है।                                            |
| Completion endpoint से पूछना कि कोई id मौजूद है या नहीं | एक टोकन भी एक बिल किया गया अनुरोध है, और अनजान model का 404 बिना-अधिकार वाले model के 404 से अलग नहीं दिखता। `assertTokenFreeUrl` ऐसा URL सीधे अस्वीकार करता है। |
| प्रदाता दस्तावेज़ों का HTML स्क्रैप करना                | निःशुल्क, पर बिना संस्करण और layout पर निर्भर। models.dev वही विनिर्देश एक स्थिर JSON अनुबंध के पीछे पहले से समेटता है।                                          |

## कैशिंग

लाइव उत्तर प्रति स्रोत और प्रति tool **कम से कम एक घंटे** के लिए Hive Mind की state
directory में कैश किए जाते हैं। `HIVE_MIND_MODEL_CATALOGUE_TTL_MINUTES` इस न्यूनतम
सीमा को केवल _बढ़ा_ सकता है: कम अवधि का अर्थ होगा प्रदाताओं से अधिक बार पूछना, और
कैश ठीक इसी को रोकने के लिए है। `--refresh` (और `/models --refresh`) केवल उस एक run
के लिए कैश को अनदेखा करता है, सहेजे गए TTL को बदले बिना।

किसी स्रोत का विफल होना घातक नहीं है और कैश को दूषित नहीं करता — पिछला सही उत्तर
`stale` चिह्न के साथ फिर से उपयोग होता है, और विफलता स्रोत-सूची में छपती है ताकि
आप देख सकें कि कैटलॉग _ऐसा क्यों_ दिख रहा है।

## CLI को अद्यतन रखना

पुराना `claude` या `codex` binary ही आमतौर पर वह कारण होता है जिससे किसी बिल्कुल नए
model का नाम अस्वीकार होता है, इसलिए जो commands उन्हें चलाती हैं वे पहले नए संस्करण
की जाँच करती हैं: `/solve`, `/hive`, `/task`, `/fix` (उसके द्वारा शुरू किए गए
`/solve` child के माध्यम से), `hive-models` और `/models`।

यह जाँच जानबूझकर संकोची है:

- हर **6 घंटे में अधिकतम एक बार**, और state lock के साथ, ताकि समानांतर runs आपस में
  न टकराएँ।
- **अन्य कार्य चलते समय स्थगित।** किसी और के चल रहे solve के नीचे से CLI कभी नहीं
  बदला जाता। हर run इस जाँच से _अपने ही_ कार्य को बाहर रखता है — अन्यथा वह तंत्र, जो
  process command line देखकर व्यस्त कार्य पहचानता है, स्वयं प्रश्न पूछने वाले run को
  ही पा लेता और हमेशा के लिए टालता रहता।
- उसी CLI तक **सीमित** जिसे command चलाने वाली है। Codex के models देखना Gemini को
  दोबारा स्थापित नहीं करता।
- **कभी घातक नहीं।** registry बंद हो तो आपको केवल यह अद्यतन ही नहीं मिलता।
- `--dry-run` / `--only-prepare-command` के लिए **पूरी तरह छोड़ दिया जाता है**,
  जिन्हें कुछ भी स्थापित नहीं करना चाहिए।

एक run के लिए `--no-tool-update` से बंद करें, या वैश्विक रूप से
`HIVE_MIND_AGENTIC_CLI_AUTO_UPDATE=0` से।

## कॉन्फ़िगरेशन

| चर                                      | अर्थ                                                                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `HIVE_MIND_MODELS_HOT_LOAD=0`           | लाइव स्रोतों से बिलकुल न पूछें; केवल अंतर्निहित कैटलॉग दिखाएँ                                                         |
| `HIVE_MIND_MODELS_ROUTER=0`             | केवल router स्रोत छोड़ें, बाकी लाइव स्रोत बनाए रखें                                                                   |
| `HIVE_MIND_MODEL_CATALOGUE_TTL_MINUTES` | कैश की अवधि 60 मिनट की न्यूनतम सीमा से ऊपर बढ़ाएँ                                                                     |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`   | संबंधित प्रदाता का listing endpoint सक्षम करते हैं। इनका न होना त्रुटि नहीं — स्रोत छोड़ दिया जाता है                 |
| `HIVE_MIND_AGENTIC_CLI_AUTO_UPDATE=0`   | agentic CLI के नए संस्करण की जाँच कभी न करें                                                                          |
| `HIVE_MIND_AGENTIC_CLI_UPDATE_ONLY`     | अल्पविराम से अलग की गई अनुमत CLI सूची                                                                                 |
| `HIVE_MIND_AGENTIC_CLI_UPDATE_EXCLUDE`  | अल्पविराम से अलग की गई वर्जित CLI सूची। command की अपनी सीमा इनसे **प्रतिच्छेद** करती है, वर्जना को रद्द नहीं कर सकती |
