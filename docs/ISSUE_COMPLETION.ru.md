# Полнота решения issue перед автоматическим слиянием

Решение issue считается завершённым, только когда каждое требование issue и всех обязательных sub-issues реализовано и проверено в одном и том же pull request (issue #2406). Зелёный CI, частичная реализация или обходной путь не считаются завершением.

## Промпты и цели

Системный, начальный и продолжающий промпты всех шести инструментов (claude, codex, opencode, agent, gemini, qwen) содержат эту цель полной поставки. Её содержит и короткий промпт claude для `--minimal-restart-context`. Промпты просят инструмент задать цель через нативный API целей, если он есть, а если нет — вести постоянный чек-лист.

Codex всегда запускается с `-c features.goals=true`, и напрямую, и через agent-commander. `--auxiliary-model-calls-disabled` теперь отключает только `features.personality`: цели несут саму задачу и не являются вспомогательным вызовом.

## Создание отчёта о требованиях

После последнего push сформируйте шаблон из текущего issue, всех комментариев issue, а также всех комментариев, inline-комментариев и ревью pull request:

```bash
node /path/to/hive-mind/src/issue-requirements-snapshot.mjs OWNER/REPO ISSUE_NUMBER PR_NUMBER
```

Промпты инструментов передают абсолютный путь к установленному скрипту. Команда только читает GitHub и печатает шаблон; каждая запись начинается со статуса `pending`. Добавьте требования из текста, которые извлекатель чек-листов не распознаёт. Для каждого требования укажите проверяемые доказательства и меняйте статус на `done` только после завершения. Требование, которое невозможно выполнить, отметьте как `blocked` с доказательством блокировки. Вставьте весь отчёт вместе с маркерами в описание pull request:

```text
<!-- hive-mind:requirements:start -->
...сгенерированный JSON-отчёт...
<!-- hive-mind:requirements:end -->
```

Сформируйте отчёт заново после нового коммита или нового отзыва в issue или ревью. Когда hive-mind переписывает описание-заглушку, существующий отчёт сохраняется.

## Что разрешает слияние

Общая функция слияния, используемая `--auto-merge`, очередью слияния и проверками после решения, требует:

- Положительные закрывающие ссылки на каждый обязательный issue (существующая проверка ссылок).
- Ровно один корректный отчёт, охватывающий ровно обязательные issues.
- Текущий SHA head pull request и дайджесты источников, совпадающие с текущими issue и отзывами.
- Каждый явный критерий приёмки со статусом `done` и непустыми доказательствами.

Каждое чтение GitHub должно завершиться успешно; нечитаемый или некорректный ответ блокирует слияние. Команда слияния также передаёт `--match-head-commit`, чтобы параллельный push не мог быть слит без проверки. Pull request без связанного issue сливаются как раньше.

## Перезапуски до завершения

После решения hive-mind перезапускает инструмент, пока отчёт не пройдёт проверку, без каких-либо дополнительных флагов. По умолчанию выполняется три перезапуска; `--ensure-all-sub-issues-addressed=N` задаёт предел. Перезапуски прекращаются раньше при исчерпании лимитов использования, повторяющихся сбоях инструмента или проверки, а также когда остались только требования `blocked`. Тогда pull request остаётся неслитым, а комментарий о блокировке слияния перечисляет оставшуюся работу вместо совета слить вручную.

## Ограничения

Отчёт — это перечень доказательств, а не доказательство выполнения произвольных требований в свободной форме. Доказательства по-прежнему должны проверять люди. Администратор репозитория может выполнить слияние вне hive-mind.
