# Case study for issue #4143

An operator, or an automated redeploy, could not ask a running `hive-telegram-bot` whether it was idle. The solve queue lived only in memory. Isolated tasks were visible only as Docker containers labelled `start-command.uuid`, and non-isolated tasks only as `solve`/`hive` processes inside the bot container. Queued work that had not started was invisible, and a restart lost it. A redeploy had to guess from `docker ps` and `docker top`. [Issue and comment](issue.md) · [Original issue](https://github.com/link-assistant/hive-mind/issues/4143) · [PR #4146](https://github.com/link-assistant/hive-mind/pull/4146)

The fix adds a durable instance state that the bot keeps current, so `hive-telegram-bot --status` can read it without a bot token. The state is written to two stores that must agree: an indented Links Notation file and a link-cli doublets store with the transactions log enabled. On top of that come a drain mode for safe redeploys, restore of queued tasks and subscribers after a restart, and eight upstream reports for the defects found in link-cli, links-notation and lino-objects-codec. Six of them were fixed within a day, and a recheck against those releases found the last two.

## Root causes

1. **No published state.** The solve queue (`src/telegram-solve-queue.lib.mjs`) and the active-session map existed only in the bot's memory. No file or endpoint exposed them, and nothing survived a restart.
2. **No intake control.** There was no switch that stopped new work while letting running work finish, so a redeploy could only stop the bot and kill whatever was running.
3. **Upstream defects found while building the two stores:**
   - **link-cli concurrency.** Every save writes `<db>.saving` and then renames it over the database. The CLI takes no lock, although `FileLock` exists in the library. With 12 concurrent writers, 8 exited 0 but only 2 links remained: [log](../../../experiments/issue-4143/concurrent-repro.log).
   - **link-cli transactions.** With `--transactions`, every write loads and rewrites the whole transitions store. Write 40 took 4076 ms (names file 208,949 bytes) against 23 ms without transactions: [with](../../../experiments/issue-4143/perf-tx.log), [without](../../../experiments/issue-4143/perf-plain.log). `--retention sized:64` does not bound the names file.
   - **links-notation.** An empty `""`/`''` at the end of a line pairs with the next quote on a later line. A value starting with `#` is silently dropped as a comment, and an unquoted `:` is a syntax error: [repro log](../../../experiments/issue-4143/upstream-links-notation-repro.log).
   - **lino-objects-codec.** `formatIndented` writes `''` and bare `#x`, so its output loses data when read with the links-notation `Parser`. It also flattens nested objects into sections with generated ids: [repro log](../../../experiments/issue-4143/upstream-codec-repro.log).

## Solutions

- **State model.** A single tree holds `version`, `instance` (id, PID, host, PID namespace, start time, heartbeat, launching count), `intake`, `tasks` and `subscribers`. The publisher writes it when something changes, checking every 5 s (`HIVE_MIND_STATE_PUBLISH_INTERVAL_MS`), and at least once per 60 s heartbeat. It marks the instance stopped on shutdown. `--status` derives whether the instance is alive from the heartbeat age and, on the same host and PID namespace, from whether its PID exists.
- **Drain handshake.** `--drain` writes `intake.state = draining` with a request time. The bot sees the request within one publish interval, rejects new commands and writes `acknowledgedAt`. `--wait-for-idle` returns 0 only after the acknowledgement, once no task is running, starting or launching. It returns 1 on `--wait-timeout`, and the example script then resumes intake.
- **Dual store.** The tree is written to `.lino` first, then to link-cli, under the state lock. Reads compare the two copies, retry while they differ, and fall back to `.lino`, the copy written first. Values that link-cli would treat as ids or that the parser misreads are stored as `~b64_` references.
- **link-cli usage.** All `clink` calls run under the external PID lock, with per-process temporary files and a timeout (`HIVE_MIND_STATE_LINKS_TIMEOUT_MS`, 30 s), and every call is timed in the verbose trace.
  - Every import and export passes `--indexed-lookups`, because every leaf of the state is a named link (below).
  - A first write, and a rebuild once garbage outgrows the live tree four times, import into a fresh store without `--transactions` and rename it into place (#199). Later writes import into the store with `--transactions`.
  - Long lists are split into content-addressed named links (`~c<sha256>`) so no input line nests deeper than 32 levels (#200).
  - On link-cli 3.1.x only, the marker log is rotated above `HIVE_MIND_STATE_LINKS_LOG_MAX_BYTES` (64 KiB); 3.2 compacts its journal itself (#195).
  - `HIVE_MIND_CLINK=off`, or a missing binary, runs `.lino`-only and `--status` reports it.
- **Locks.** A `mkdir` lock directory with `owner.json` (PID, host, PID namespace, time):
  - `pid` mode breaks the lock at once when the owner is dead on the same host, and after the stale age otherwise.
  - `age` mode uses the age only.
  - `none` mode disables locking.
- **hive-manager (#4145, PR #4148).** `hive-manager deploy update` refuses to replace an instance that runs tasks. It finds them through start-command and `/proc`, and `--wait` waits for them. That check cannot see queued requests, and a task can still start between its last check and the stop. Running `hive-telegram-bot --drain` and `--wait-for-idle` first (as `box`, through `docker exec`) closes both gaps: intake stops and the queue is kept in the state files. `docs/deployment/hive-manager.md` documents this order. hive-manager does not drain automatically, because an older image without `--drain` would start a second bot instead of failing.

## Prior art and libraries

- **Drain and quiesce patterns.**
  - Kubernetes sends `preStop` and `SIGTERM`, then waits `terminationGracePeriodSeconds` while endpoints stop routing new traffic. [Pod termination](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/)
  - Sidekiq's `TSTP` signal makes a process "quiet": it stops fetching jobs and finishes the current ones. This is the closest match to `--drain`. [Sidekiq signals](https://github.com/sidekiq/sidekiq/wiki/Signals)
  - Celery's `cancel_consumer` stops a worker consuming from a queue without stopping it. [Celery workers](https://docs.celeryq.dev/en/stable/userguide/workers.html)
  - systemd's `sd_notify` `STATUS=` and `STOPPING=1` publish a free-form status and a stopping state for a supervisor. [sd_notify](https://www.freedesktop.org/software/systemd/man/latest/sd_notify.html)
  - Docker `HEALTHCHECK` covers liveness only, not intake or the queue. [Dockerfile reference](https://docs.docker.com/reference/dockerfile/)
  - None of these persists a queue across restarts. That is why the state lives in files in a mounted directory.
- **Atomic files and locks.**
  - `rename(2)` within one file system is atomic, which `.lino` writes rely on. [rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html)
  - `flock(2)` locks are released by the kernel when the process exits, which is what link-cli's `FileLock` uses. [flock(2)](https://man7.org/linux/man-pages/man2/flock.2.html)
  - `proper-lockfile` uses `mkdir` with mtime staleness, like hive-mind's `age` mode. The `pid` mode adds owner-liveness checks so a crashed bot does not block for the stale period. [proper-lockfile](https://github.com/moxystudio/node-proper-lockfile)
- **Links libraries.**
  - links-notation is the parser that both stores are checked against.
  - lino-objects-codec has an indented format, but it does not survive that parser and is not nested. hive-mind therefore has its own small nested formatter.
  - link-cli provides the doublets store and the transactions log.

**New findings in link-cli 3.2.1:**

1. **One transaction per created link** ([#199](https://github.com/link-foundation/link-cli/issues/199), open). Each auto-commit runs a full store save and a journal `fsync`, so a first `--in --transactions` of a 10-task state took 10.5 s. A crash mid-import leaves a prefix of the links applied ([clink-import-crash-atomicity-3.2.1.log](../../../experiments/issue-4143/clink-import-crash-atomicity-3.2.1.log)). hive-mind now builds a fresh store without `--transactions` and renames it into place for first writes and rebuilds: 10 tasks in 44 ms, and the old store stays readable until then.
2. **`--in` nesting limit of 64** ([#200](https://github.com/link-foundation/link-cli/issues/200), open). This was also a hive-mind bug. The doublets encoder wrote the whole state as one nested line, so a state with about 50 tasks failed to import ([clink-in-nesting-limit.log](../../../experiments/issue-4143/clink-in-nesting-limit.log)). Lists are now split into content-addressed named links, so every line nests at most 32 levels. The test "long lists stay under the link-cli nesting limit of 64" checks 300 tasks with 80 arguments each.
3. **Named lookups scan the names store by default.** Every state leaf is a named link. Without `--indexed-lookups`, each name operation scans all names, so import and export grow quadratically ([clink-import-quadratic.log](../../../experiments/issue-4143/clink-import-quadratic.log)). 400, 800 and 1200 named lines took 4.6, 19.1 and 44.4 s to import and 6.1, 25.2 and 67.6 s to export. With the flag, 1200 lines take 0.28 s and 0.21 s, and 4800 lines 0.92 s and 0.75 s. link-cli#110 added the index as an opt-in decorator and documents the scan as a known limit, so this was not reported again. hive-mind now passes the flag.

## Remaining limits

- A non-isolated task runs inside the bot container and stops when the container restarts. It is reported as `running` until then, and it is not restarted, because its partial work cannot be resumed safely. Isolated tasks keep running in their own containers, and their sessions are tracked by the existing session store.
- Tasks that were `starting` when the bot stopped are not re-enqueued, since their launch may already have happened. `--status` shows them and the operator decides.
- `--status` judges liveness by PID only on the same host and PID namespace. From another host, it relies on the heartbeat age (3 × 60 s).
- Native Link CLI schema migrations are still open in [link-cli#209](https://github.com/link-foundation/link-cli/issues/209). Hive Mind can migrate its own documents in both directions through the shared migration table.
- A link-cli older than 1.0.9 has no `--indexed-lookups`. Set `HIVE_MIND_STATE_LINKS_INDEXED_LOOKUPS=off` for it, and expect the scan timings above.
