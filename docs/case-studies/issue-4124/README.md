## Root cause and implementation scope

The upstream API-key default was five minutes for both request buckets. An included Claude subscription can give the main conversation an hour while most requests outside it still get five minutes. Hive Mind's stock Claude environment and user settings declared neither control. Long build and review gaps could therefore expire a stable subagent prefix even when the parent application's prefix stayed warm. Subagents build their own prefix from their own instructions and tools. A subagent's initial request normally warms that prefix, while a resumed subagent can read it if it is still warm. [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)

Claude Code 2.1.242 and later supports two explicit environment variables and two JSON settings. The stock images pin 2.1.319. Hive Mind supplies the two variables for managed runs and honors a valid process override for each. `FORCE_PROMPT_CACHING_5M=1` takes precedence over both, and the Docker task and `start-agent` boundaries carry it explicitly. The runtime configuration and `hive-manager configure-claude` seed both native settings and preserve valid existing `5m` or `1h` values. Copy-paste Claude commands from native runs use that user configuration. Auth and version probes without inference have no prompt to cache. [Claude Code environment variables](https://code.claude.com/docs/en/env-vars) · [Claude Code settings reference](https://code.claude.com/docs/en/settings-reference)

Setting only JSON values could miss a restricted launch or a container with a mounted configuration. Setting only variables would leave a later standalone run outside the managed environment on upstream defaults. `ENABLE_PROMPT_CACHING_1H=1` is a low-priority fallback behind both explicit settings and subagent frontmatter. The two named variables make the managed policy independent for each bucket and match the requested control. The tradeoff is that a managed run's bucket variable takes precedence over a lower-priority JSON setting or subagent frontmatter. To select five minutes in a managed run, supply the corresponding bucket variable or use the global override. [Claude Code prompt caching precedence](https://code.claude.com/docs/en/prompt-caching#choose-the-ttl-yourself)

## Cost and limits

The issue reports 116.6 million cache-write tokens and 159 full rewrites of 200,000 to 900,000 tokens in two days. The reported 20–25% savings estimate depends on that operator's idle intervals, prefix lengths and cache usage. The issue supplies aggregate numbers, so the estimate cannot be recomputed from per-request activity. A prior Hive Mind incident independently recorded a Claude Opus 4.8 result with 71,030 one-hour write tokens and 2,311,299 cache-read tokens. Hive Mind already rates both types of writes correctly and includes TTL-split counters in its budget statistics. [Issue report](data/issue.json) · [Issue #1951 cost evidence](../issue-1951/analysis.md) · [Claude cost code](../../../src/claude.cost.lib.mjs) · [Budget statistics](../../../src/claude.budget-stats.lib.mjs)

Per equal-length reusable prefix, measured in units of the base input price, a five-minute write costs 1.25, an hour write costs 2, and a read costs 0.10. These are provider API list-price calculations. They do not estimate how subscription usage translates into its weekly quota. [Claude Platform cache pricing](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

| Two accesses to the same prefix                      | 5m policy | 1h policy |
| ---------------------------------------------------- | --------: | --------: |
| Both in the five-minute window                       |      1.35 |      2.10 |
| Second access after five minutes and before one hour |      2.50 |      2.10 |
| Second access after one hour                         |      2.50 |      4.00 |

In the middle case, the longer write adds 0.75 but avoids a 1.25 rewrite in exchange for a 0.10 read. For short bursts or one-shot tasks, the priority can instead be lower write cost. Reuse also depends on matching the model, speed, tool list, prefix and workspace conditions. Longer TTL cannot recover hits from a changed prefix. Keep stable instructions and tools early in the request, use short summaries to hand off finished phases, and compare `cache_read_input_tokens` with `cache_creation_input_tokens` and the `ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens` breakdown. Changing the subagent lifecycle automatically would add handoff and warm-up costs, so the case study retains handoffs as an operator decision. [Claude Code cache scope and metrics](https://code.claude.com/docs/en/prompt-caching) · [Claude Agent SDK cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

Gateways using `ANTHROPIC_BASE_URL` need to preserve Anthropic's beta header, and Bedrock availability depends on the model and region. The experiment confirms the CLI emits the on-wire controls for a known prefix. Real hit rates and bills require provider usage counters from a production workload. [Claude Code gateway and Bedrock guidance](https://code.claude.com/docs/en/prompt-caching#choose-the-ttl-yourself)

## Other supported tools

The versions below are those in the stock Hive Mind image. Cache keys, cache lifetimes and retention/billing differ by protocol. The default routing in Hive Mind can include native authentication, a compatible Router or a Formal AI sidecar. A blanket cache-lifetime knob would change policy for any of those routes that happened to accept it. The solution reuses Claude's native controls, Hive Mind's managed environment and `configure-claude`, and the existing Anthropic usage and public-pricing code. Vendor adapters already handle provider cache markers and token accounting. Adding a cache service or a transport-level payload rewriter would duplicate that work and require it to own provider-specific billing, compatibility, and breakpoint selection. An OpenCode TTL plugin is an alternative for an operator with a validated route, while the version-pinned native option avoids installing another dependency for this task. [OpenCode TTL plugin](https://github.com/klaveren/opencode-cache-ttl)
