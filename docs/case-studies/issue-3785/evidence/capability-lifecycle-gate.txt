Issue #3785 PR review (comment 6559288409): installed capability lifecycle gate
================================================================================
Gate: scripts/verify-capability-lifecycle.mjs (+ capability-lifecycle-state.lib.mjs,
capability-lifecycle-provider.lib.mjs). Required in docker-pr-check for both the
host-socket and the nested Docker daemon images (scripts/docker-pr-verify-mount-backing.mjs).

Local runs below: 2026-11-01, Linux, installed hive from this branch, real
installed claude 2.1.316 / codex 0.166.0, synthetic credentials only. Every
Anthropic/OpenAI API, OAuth and account host is answered by the loopback
provider with a throwaway CA; only package/binary download hosts are tunnelled.
The provider answers Claude's account-sync gates as if sync were enabled for a
Max organization (forceAccountSync), so a clean result proves the local
configuration alone keeps sync off. Output carries counts and synthetic names only.

Checkpoint after every phase:
  - capability manifest (independent scanner, names only, never reads contents) is empty
  - production audit (runAgentConfigAudit, requireClean, no repair) has 0 findings
  - 0 account-sync / curated-catalog / hosted-connector requests or tunnels
  - canonical auth + history: same bytes and same inode/device; history journals
    may only be appended to (restore phase: content only)

  claude:plugin) never describe a cached item as enabled.

  canonical credentials file byte- and inode-identical. The empty Claude token

  and were not re-authenticated; this gate shows that neither the CLI installer

  them. Such a store needs an operator re-login (Hive reports re-auth required).
