# 生产任务恢复

Telegram 机器人、主机上的 `solve` 和 Docker 任务镜像应使用经过审核的版本。更新主机上的软件包不会替换已经运行的机器人，也不会更新本地缓存的任务镜像。

## 升级与验证

2026 年 10 月的事故中，主机仍在运行 2.33.11，而模型推理设置的修复已在 2.33.13 发布。应升级到包含该修复及本 PR 恢复改进的审核版本。

1. 记录 `solve --version`、`hive-telegram-bot --version`、任务镜像及其摘要。使用 `npm view @link-assistant/hive-mind version` 查看已发布的软件包版本。
2. 对于 npm 安装，执行 `npm install -g @link-assistant/hive-mind@<version>`，然后通过现有服务管理器重启机器人。确认服务实际使用更新后的可执行文件，而不是 PATH 中的另一份安装。
3. 拉取选定的 `konard/hive-mind` 或 `konard/hive-mind-dind` 镜像标签。显式更新固定的镜像引用。Coolify 部署需要拉取或重建镜像并重新部署，同时保留现有凭据挂载和任务设置。
4. 确认主机及下一个隔离任务的启动日志都显示预期的 Hive Mind 版本，并记录任务镜像摘要。
5. 使用生产工具、模型和推理设置运行一个小任务。Codex 在启动前根据 CLI 能力目录解析推理强度；不兼容的配置会在创建任务容器前失败。

## 身份验证

Docker 任务启动前，主机会检查 Claude/Codex 订阅访问权限；检查发生在辅助容器、镜像拉取及任务容器创建之前。认证被拒绝时，新 CLI 进程尝试刷新凭据一次，然后重新检查使用量。每次检查最多 15 秒，刷新进程最多 20 秒。刷新可能发起一个小型模型请求。同一工具和凭据路径的并发检查共享一次探测。

如果仍无法恢复，启动错误及 Telegram 回复会提示在主机上重新登录。该工具的待执行任务暂停，直到凭据文件发生变化。在提供挂载凭据的主机上执行 `claude /login` 或 `codex login --device-auth`。文件变化后，下一个任务可以重新检查。其他工具队列继续执行各自的检查。运行中的 Claude 会话失去访问权限时，也只使用一个新 CLI 进程重试一次；成功刷新不会输出终止队列的标记。

使用量 API 故障及 HTTP 429 不代表凭据无效。API 密钥、路由器和 Formal AI 任务跳过订阅检查；API 密钥仍由正常提供商执行验证。暂停状态保存在机器人进程中，重启后由预检重新建立。现有 `/hive` 工作进程遇到终止访问标记会停止；重新登录后需要重启 `/hive`。

共享凭据的 inode、原子替换及刷新锁问题单独记录在 [#2296](https://github.com/link-assistant/hive-mind/issues/2296)。本次预检和重试不改变凭据挂载方式。

## 重启预算耗尽和模型拒绝

自动重启预算耗尽后，整体运行失败，PR 保持草稿，并发布一条说明剩余阻塞原因及失败 CI 检查的摘要。评论记录 PR 提交。自动 `/hive --auto-continue` 重新入队会将该提交延后六小时。机器人环境变量 `HIVE_MIND_AUTO_RESTART_COOLDOWN_HOURS` 可调整间隔，`0` 表示禁用。新的 PR 提交，或新增、编辑的问题评论、PR 评论、行内评论及审核反馈会解除冷却；会话及日志自动评论不会。延后的问题仍可在后续队列迭代中检查。手动 `solve` 仍然可用。

Codex 网络安全拒绝属于终止错误。问题或 PR 报告会说明模型拒绝了任务，并建议 `--tool claude` 或重新表述请求；不会进入临时错误重试循环。

## 保存工作与停止的容器

严重错误恢复使用独立 Git 索引，把符合条件的未提交工作快照保存并推送到 `recovery/<task-branch>`。PR 分支、工作树及正常索引仍供下一会话使用。最多 5 MiB 的未跟踪二进制文件会被保存，包括 `docs/`、`tests/`、`fixtures/` 和 `experiments/` 中的截图及测试数据。扩展名或 NUL 字节本身不能证明文件属于构建输出。已知构建目录会被排除；过大或无法读取的文件会记录明确原因，并阻止生成完整保存凭证。

当 `HIVE_MIND_KEEP_TASK_CONTAINER=on-failure` 时，完成监视器只有在系统恢复凭证确认日志已上传且工作已完整远程保存后，才移除认证失败、模型拒绝或重启预算耗尽的容器。推送的恢复提交包含父提交历史；没有恢复提交的干净工作树，其 HEAD 必须与远程任务分支一致。上传失败、推送失败、保存状态不明、过大文件或未推送提交都会保留容器。远程保存不完整时也禁用工作区自动删除，以便容器中仍保留工作。`always` 始终保留容器。完成后的删除使用不带强制选项的 `docker rm`，因此不会删除已恢复运行的容器。原有 `none` 策略仍可使用。

启用 `--attach-logs` 才能依据已保存证据自动清理。独立 start-command 生命周期、TTL 扫描和恢复镜像清理另见 [#2629](https://github.com/link-assistant/hive-mind/issues/2629) 和 [#2630](https://github.com/link-assistant/hive-mind/issues/2630)。

## 退出码 137

退出码 137 本身不能证明内存不足。应结合现有 cgroup `memory.events`、`oom_kill` 诊断和完成报告中的 Docker 状态。在增加内存或交换空间前，检查容器内存限制和主机余量。本次修改不改变生产资源限制或已有 OOM 恢复路径。保存不完整时应保留容器并先调查报告的故障。
