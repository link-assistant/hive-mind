# Issue 4095 — One Hive Mind maintenance entry point

[Issue #4095](https://github.com/link-assistant/hive-mind/issues/4095) describes an operator workflow split between five package executables, manual Docker instructions, and Control Center scripts that assume an existing administration environment. The same operation may need to run inside the image, on the Docker host, or on a remote Docker host reached from a developer machine.

## Remaining migration and environment checks

Retiring the Control Center requires deploying the manager on the current infrastructure and migrating the workflows that automation calls today. The integration issue lists the workflows to transfer, staging checks and criteria for deciding what can be retired. [Control Center migration issue](https://github.com/link-assistant/hive-mind-control-center/issues/1)

- The pinned start-command version reconciles live tasks and recovers empty or stale store locks. The repair experiment launches a real Docker snapshot and verifies the exit status through the upstream watcher. Older containers without tracking labels and unsupported record layouts require manual investigation. Incident publication verifies the exact GitHub title and body through a fixture.
- The manager can initialize an archive and publish scheduled batches to a private destination. It writes a layout with a manifest per batch and a revision index. The Git migration fixture preserves existing legacy transcripts and metadata in the destination tree. The index covers manager revisions, so a source transcript may appear in both layouts during a rollout. The historical archive needs access to confirm the migration and transfer its scheduler. The Control Center records an original identity-data leak in its archive history, so preserve that repository’s privacy during migration.
- Fixtures verify message and attachment round trips and failed-transfer cleanup. Live proxy validation needs the affected client network, the proxy host, and an authorized Telegram account/session. The vendor-specific mobile route setup is part of the Control Center's [verification procedure](https://github.com/link-assistant/hive-mind-control-center/blob/21eb663e08fa6d1fa5751949d4534cd88818ac64/src/hive-control-center/docs/MTProxy-VERIFICATION.md).
- The incident routing fixtures exercise log signatures and reviewed host correlations such as a hard reset versus a daemon restart. Checking the current routing configuration against historical records and transferring it to the current deployment requires access to that deployment.
- The disposable Docker experiment uses a small fixture to exercise rollout mechanics. The released-image smoke runs through the repository's Docker build workflow, which is opt-in for pull requests. Completing fresh provider enrollments requires authorized accounts, and the live Telegram task check requires an authorized bot and client route.

## Reproducing the verification

```bash
node --test tests/hive-manager-4095.test.mjs tests/hive-manager-auth-4095.test.mjs tests/telegram-after-4069.test.mjs
node tests/test-docker-release-order.mjs

bash experiments/issue-4095/task-record-repair.sh
node experiments/issue-4095/browser-diagnostics.mjs
node experiments/issue-4095/headless-auth.mjs
```

The Docker experiment verifies that a failed task file remains readable from its backup after receipt-approved removal. It also checks that image defaults are seeded once, Git and Codex data survive a replacement, bad bot configuration does not stop the active instance, a crashing candidate leaves the prior instance up, rollback selects the earlier container, and resource diagnostics show the fixture thread, browser process, shared memory and cgroup controllers available on the daemon. A process fixture leaves 24,000 bytes unread on a Unix socket pair and checks both endpoints across the sample. The SSH experiment starts disposable SSH servers to test two actual jumps with strict host-key checks, including a synthetic Claude browser prompt and code round trip without a TTY. The browser experiment uses the installed Playwright MCP package and Chrome to observe one live headless process tree and verify the read-only check leaves it running.

Run `installed-maintenance.sh` on stdin of a disposable Linux container with `--init --network none` and the packed `hive-manager` command and Node.js on `PATH`. It checks root CLI startup and writes and verifies a fresh Claude settings file. An orphaned process fixture verifies that the terminal exposes the approval digest, an incorrect approval preserves the process, and the reviewed digest lets the manager signal it.

The native auth experiment needs the provider CLIs, the bundled Git identity helper and Internet access. It stops after each browser challenge and discards the temporary configuration directories. The regression test checks the protocol handoff without an account and confirms that provider status errors propagate to the caller.

The Coolify Compose experiment renders the deployment using Docker Compose through the manager. It checks that the monitor URL reaches the service, the repository root is the build context, and the existing credential mounts remain under the Coolify directory.
