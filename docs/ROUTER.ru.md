# Изоляция через роутер (`--use-router`) (languages: [en](ROUTER.md) • [zh](ROUTER.zh.md) • [hi](ROUTER.hi.md) • ru)

> **⚠️ ЭКСПЕРИМЕНТАЛЬНАЯ ВОЗМОЖНОСТЬ.** Флаг существует, sidecar работает, а всё, что пока не покрыто, перечислено в разделе [Что пока не покрыто](#что-пока-не-покрыто) — каждый запуск с роутером выводит этот список сам. Прочитайте его, прежде чем полагаться на эту изоляцию.

По умолчанию задача, изолированная в Docker, получает реальную подписку оператора: каталоги `~/.claude`, `~/.claude.json`, `~/.codex`, `~/.agents` и `~/.config/gh` монтируются в контейнер. Агент внутри держит в руках исходные учётные данные OAuth, может тратить подписку без ограничений и не оставляет следов, кроме тех, что решил записать сам.

`--use-router` эти монтирования отменяет. Учётные данные остаются в единственном контейнере-sidecar `hive-mind-router`, каждая задача получает собственный краткоживущий токен, и каждый запрос к модели попадает в журнал, принадлежащий именно этому токену.

```bash
solve https://github.com/owner/repo/issues/42 --isolation docker --use-router
```

## Что меняется

|                        | По умолчанию            | С `--use-router`                                                            |
| ---------------------- | ----------------------- | --------------------------------------------------------------------------- |
| Учётные данные вендора | Монтируются в задачу    | Монтируются только в sidecar                                                |
| Точка доступа к модели | api.anthropic.com       | `https://link-assistant-router`                                             |
| Точка доступа к GitHub | напрямую api.github.com | api.github.com, разрешаемый внутри контейнера в адрес роутера               |
| Адрес git-remote       | github.com              | `https://link-assistant-router/git/<owner>/<repo>`                          |
| Учётные данные задачи  | Сама подписка           | Токен `la_sk_…`, выданный только этой задаче                                |
| Срок жизни токена      | —                       | 24 часа или 5000 запросов, отзывается при завершении задачи                 |
| Журнал запросов        | Отсутствует             | Один JSONL-файл с редактированием на каждый токен, сохраняется после отзыва |
| Сеть                   | Собственная сеть задачи | Задача дополнительно подключается к внутренней сети `hive-mind-router`      |

Без флага не меняется ничего. Путь по умолчанию остаётся прежним намеренно: это изоляция по запросу, а не миграция.

## Как это работает

1. **Sidecar.** Первая задача с роутером запускает `ghcr.io/link-assistant/router:0.119.0` — версия зафиксирована, поэтому релиз наверху не меняет то, с чем разговаривает задача, без коммита здесь — под именем `hive-mind-router` во внутренней сети Docker (`--internal`): внутренней — значит, у sidecar нет выхода наружу, кроме того, что даёт Docker, и с хоста до него тоже не достучаться. TLS он завершает сам на порту 443 самоподписанным сертификатом, имена в котором покрывают и `link-assistant-router`, и `api.github.com`. В него монтируются `~/.claude`, `~/.codex`, `~/.gemini` и `~/.qwen` оператора, на которые указывают `CLAUDE_CODE_HOME`, `CODEX_HOME`, `GEMINI_HOME` и `QWEN_HOME`. Это единственное место, где существует подписка (R3).
2. **Токен.** Hive Mind выпускает по одному токену на задачу через `router tokens issue`, помечая его идентификатором сессии и ограничивая ключом `--github-repo` тем единственным репозиторием, над которым работает задача. Токены никогда не используются двумя задачами сразу — именно поэтому журнал каждой задачи принадлежит только ей (R6).
3. **Задача.** Контейнер задачи подключается к сети роутера в дополнение к своей собственной и получает `ANTHROPIC_BASE_URL` (или сгенерированную запись провайдера для инструментов с OpenAI-совместимым интерфейсом), указывающий на sidecar, вместе с токеном. Claude Code отправляет через `ANTHROPIC_BASE_URL` _каждый_ запрос, включая вложенные агентские циклы, поэтому не остаётся пути, тихо обходящего прокси.
4. **Доверие и перехват.** Пока стартовые ворота ещё удерживают команду задачи, Hive Mind записывает CA роутера в контейнер, направляет `api.github.com` на роутер через `/etc/hosts` и настраивает git на отправку через `https://link-assistant-router/git/…`. Каждому клиенту про CA сообщают так, как он этого ждёт: `NODE_EXTRA_CA_CERTS` для Node, `SSL_CERT_FILE` для `gh` и клиентов на Rust — он _заменяет_ системное хранилище, поэтому им передаётся связка публичных корневых сертификатов вместе с CA роутера, — `CURL_CA_BUNDLE` для curl и `http.<url>.sslCAInfo` для git. Немодифицированный `gh` поэтому попадает в роутер, не зная о его существовании, а собственного токена GitHub у задачи нет (R12).
5. **Formal AI.** У запуска с `--model formal-ai` два sidecar'а. Роутер подключается к сети Formal AI и сохраняет этот sidecar как провайдера (`router providers add`), поэтому модель обслуживается _через_ роутер и журналируется как любая другая (R11). Другие задачи это не перенаправляет: роутер выбирает провайдера по идентификатору модели.
6. **Аренда.** Sidecar учитывается по арендам, а не булевым флагом. Он работает, пока хотя бы одна задача держит аренду, и останавливается, когда освобождена последняя (R5). Остановка никогда не затрагивает том с данными.
7. **Завершение задачи.** Когда аренда снимается, каталоги `~/.claude`, `~/.claude.json` и `~/.codex` задачи копируются в том роутера в `task-sessions/<sessionId>/`, и только после этого токен отзывается (R7). `docker cp` работает и с остановленными контейнерами, поэтому упавшая или убитая задача выгружается так же надёжно, как завершившаяся штатно.

Убитый бот или перезагруженный хост не могут оставить sidecar работать вечно: Telegram-бот раз в пять минут сверяет аренды с Docker и останавливает sidecar, которым не пользуется ни одна живая задача. Аренды моложе часа сохраняются в любом случае, поэтому у ещё запускающейся задачи sidecar из-под ног не выдернут.

## Журнал аудита

Смысл всей конструкции в том, чтобы потом можно было ответить на вопрос «что этот агент на самом деле делал?».

- `requests/<token-hash>/requests.jsonl` — каждый запрос этого токена, с редактированием.
- `audit.jsonl` — по строке на каждый разрешённый запрос: время, идентификатор токена, метка сессии, с которой он был выпущен, провайдер, интерфейс, путь и модель.
- `task-sessions/<sessionId>/` — собственные записи сессии агента, выгруженные из контейнера до его удаления.

Всё это лежит в именованном томе `hive-mind-router-data`, который **не удаляется ни одним путём кода Hive Mind**. Он переживает sidecar; остановка или пересоздание роутера его не затрагивает. О том, как прочитать его обратно — в том числе когда роутер не запущен, — см. [Сбор журналов](./COLLECTING-LOGS.ru.md):

```bash
node examples/collect-logs.mjs --out ./audit
```

## Настройка

| Переменная                           | Значение                                                                                                      |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `HIVE_MIND_USE_ROUTER=1`             | То же, что `--use-router`; так решение наследуют бот и вложенные запуски `solve`                              |
| `HIVE_MIND_ROUTER_URL`               | Использовать уже запущенный роутер вместо sidecar. Должен быть «голым» источником `http(s)://host[:port]`     |
| `HIVE_MIND_ROUTER_TOKEN`             | Токен для внешнего роутера. Обязателен, если задан `HIVE_MIND_ROUTER_URL`                                     |
| `HIVE_MIND_ROUTER_SIDECAR=0`         | Никогда не запускать и не останавливать sidecar (для операторов, управляющих роутером самостоятельно)         |
| `HIVE_MIND_ROUTER_IMAGE`             | Переопределить образ роутера                                                                                  |
| `HIVE_MIND_ROUTER_ROUTES`            | Задать диалект маршрутов, `legacy` или `canonical`, когда тег образа о нём не говорит (дайджест или `latest`) |
| `HIVE_MIND_ROUTER_EXTRA_ARGS`        | Дополнительные аргументы `docker run` для sidecar                                                             |
| `HIVE_MIND_ROUTER_TOKEN_SECRET`      | Задать секрет подписи токенов вместо генерации                                                                |
| `HIVE_MIND_ROUTER_GH_HOST`           | Ходить в GitHub через этот HTTPS-хост вместо перехвата `api.github.com` (нужно для внешнего роутера)          |
| `HIVE_MIND_ROUTER_GITHUB=0`          | Совсем не маршрутизировать трафик GitHub; задача сохраняет собственные учётные данные `gh`                    |
| `HIVE_MIND_ROUTER_DRAIN_SESSIONS=0`  | Не архивировать данные сессии при завершении задачи                                                           |
| `HIVE_MIND_SESSION_ARCHIVE_DIR`      | Архивировать данные сессии в этот каталог на хосте вместо тома роутера                                        |
| `HIVE_MIND_GIT_HOOKS_DIR`            | Каталог на хосте, где создаётся страж `pre-push` (по умолчанию `~/.hive-mind/git-hooks`)                      |
| `HIVE_MIND_ALLOW_DESTRUCTIVE_PUSH=1` | Всё же разрешить задаче с роутером принудительную отправку и удаление удалённых ссылок                        |

### Секрет подписи

Секрет, которым подписываются токены, создаётся один раз и хранится в каталоге состояния бота с правами `0600`. Любой, у кого он есть, может выпускать токены к подписке, поэтому:

- он никогда не попадает в окружение задачи;
- он никогда не записывается в журнал;
- `examples/collect-logs.mjs` намеренно отказывается копировать каталог состояния в архив с доказательствами и вместо этого сообщает путь к нему.

Если вы задаёте собственный секрет через `HIVE_MIND_ROUTER_TOKEN_SECRET`, относитесь к нему как к корневым учётным данным.

## Версии роутера и диалекты маршрутов

Роутер `1.0.0` заменил все публичные маршруты и удалил прежние, поэтому у двух поколений **нет** ни одного общего пути. Если опросить `0.119.0` и `1.2.0` рядом ([`experiments/issue-2202/compare-router-routes.sh`](../experiments/issue-2202/compare-router-routes.sh)), столбцы не пересекаются: каждый путь, отвечающий на одном, — это `404` на другом:

| Назначение          | `legacy` (роутер `< 1.0`) | `canonical` (роутер `>= 1.0`)      |
| ------------------- | ------------------------- | ---------------------------------- |
| Здоровье            | `/health`                 | `/api/health`                      |
| Claude / Anthropic  | `/` (корень)              | `/api/services/anthropic`          |
| Codex, OpenAI       | `/v1`                     | `/api/services/codex/v1`           |
| GitHub REST         | `/api/v3`                 | `/api/services/github/api/v3`      |
| GitHub GraphQL      | `/api/graphql`            | `/api/services/github/api/graphql` |
| Транспорт git       | `/git/`                   | `/api/services/github/git/`        |
| Управление токенами | —                         | `/api/management/tokens`           |

Hive Mind говорит на обоих и выбирает диалект по тегу `HIVE_MIND_ROUTER_IMAGE`: мажорная `0` — это `legacy`, `1` и выше — `canonical`. Тег без версии — дайджест или `latest` — считается `canonical`; чтобы указать иное, задайте `HIVE_MIND_ROUTER_ROUTES`. Больше менять ничего не нужно: проба здоровья, базовые URL каждого инструмента, `config.toml` для Codex, префикс `insteadOf` для git и точки входа каталога моделей выводятся из диалекта.

**Закреплённая по умолчанию версия остаётся `0.119.0`, и это осознанный компромисс.** В `canonical` прокси GitHub примонтирован только под `/api/services/github/…`, а `gh` строит REST-базу произвольного хоста как `https://<host>/api/v3/` и не имеет настройки префикса пути — поэтому на роутере `1.x` вызовы `gh api` и GraphQL из задачи **не** опосредованы. `git` это не затрагивает: `url.<prefix>.insteadOf` принимает произвольный префикс. Сдвиг закреплённой версии удалил бы возможность, описанную на этой странице, поэтому он ждёт [router#415](https://github.com/link-assistant/router/issues/415). Если новая поверхность нужна, направьте `HIVE_MIND_ROUTER_IMAGE` на образ `1.x`; перед стартом запуск напечатает пробел по `gh`.

Привязка учётных данных одинакова для обоих диалектов: монтирование `~/.claude`, `~/.codex`, `~/.gemini` и `~/.qwen` вместе с соответствующими переменными `*_HOME` по-прежнему остаётся тем, как роутер получает подписки, а `router auth import` **не** нужен — импорт без аргумента читает домашний каталог самого вендора, а не роутера, и потому не находит, что принимать. Измерено в [`docs/case-studies/issue-2202/data/measurements/router-credentials-and-tokens-2026-09-04.md`](./case-studies/issue-2202/data/measurements/router-credentials-and-tokens-2026-09-04.md).

## Разрушительные операции git

Требование R13 из issue — лишить агентов физической возможности уничтожать данные. Его закрывают три слоя; вместе они пропускают к серверу только принудительную отправку, сделанную с `--no-verify`.

| Слой                                                                    | Что покрывает                                                                                                                                    | Как обходится                                                             |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| [Защита веток](./BRANCH_PROTECTION_POLICY.ru.md) на стороне репозитория | Принудительная отправка и удаление защищённой ветки                                                                                              | Изнутри задачи не обходится                                               |
| Хук `pre-push` в каждой задаче с роутером                               | Удаление любой удалённой ссылки и любая отправка, отбрасывающая коммит, который уже есть на сервере, — форма `git reset --hard` + `push --force` | `git push --no-verify`                                                    |
| Транспорт git через роутер                                              | **Удаление** ссылок и **не-fast-forward** обновления: роутер сам отвечает HTTP 403 — изнутри задачи это не обходится                             | Разрешающее правило для конкретной ссылки, заданное оператором на роутере |

Хук создаётся на хосте в `~/.hive-mind/git-hooks` (`HIVE_MIND_GIT_HOOKS_DIR`) и монтируется в задачу **только для чтения**, поэтому задача не может изменить правило, которому подчиняется. Git направляется на него через `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0=core.hooksPath`, а не через `git config --global`: файл `~/.gitconfig` в контейнере — это собственный файл оператора, примонтированный с хоста.

Обычные отправки, новые ветки и новые теги не затрагиваются, а сам страж существует только в задачах с роутером. `--allow-fork-divergence-resolution-using-force-push-with-lease` переносит уже данное оператором согласие на принудительную отправку внутрь контейнера; `HIVE_MIND_ALLOW_DESTRUCTIVE_PUSH=1` делает то же самое вручную.

Третий слой на месте: задача с роутером отправляет изменения через `https://link-assistant-router/git/<owner>/<repo>`, собственных учётных данных GitHub у неё нет, и `git push origin :branch` возвращается с `HTTP 403` от роутера. Принудительная отправка тоже отклоняется, начиная с роутера `0.110.0`: роутер спрашивает у compare-API GitHub, опережает ли предлагаемая вершина текущую, и передаёт packfile только если да, а при любом ответе, которому он не доверяет, отказывает сразу ([router#272](https://github.com/link-assistant/router/issues/272), исправлено в [router#273](https://github.com/link-assistant/router/pull/273)). В этом репозитории закреплён `0.119.0`, так что этот слой работает.

Измерение проводилось на `0.109.0`, до исправления, и с тех пор версия менялась дважды без повторного прогона пробы — см. `experiments/issue-2164/probe-git-transport.sh`, если нужна текущая цифра, а не записанная.

Второй слой — «лежачий полицейский», а не клетка: агент, прочитавший эту страницу, сможет его обойти. Он устраняет случайность, но не злой умысел, поэтому для принудительных отправок единственным необходимым контролем остаётся защита веток.

## Что пока не покрыто

Каждый запуск с роутером выводит этот список перед стартом. Это честные границы экспериментального состояния:

- **Разрушительные вызовы GitHub API блокируются по методу, а не по последствию** ([router#329](https://github.com/link-assistant/router/issues/329)). Роутер отклоняет любой `DELETE`, принудительные обновления ссылок через REST и разрушительные мутации GraphQL. Но те же последствия, записанные иначе, он не отклоняет: `PUT /repos/{o}/{r}/branches/{b}/protection` целиком заменяет объект защиты, `PUT .../rulesets/{id}` ослабляет ruleset, `POST .../transfer` передаёт репозиторий другому владельцу, а `PATCH /repos/{o}/{r}` может изменить `visibility`, `archived` или `default_branch`. Защита веток достижима этим путём, поэтому считайте её надёжной настройкой по умолчанию, а не контролем, до которого задача не дотянется, и держите всё, что не должно меняться, вне области действия токена (`--github-repo`). На практике ограничено правами того `gh`-кредентиала, который роутер предъявляет наверх.
- **Собственные исходящие запросы sidecar'а Formal AI не маршрутизируются.** `--model formal-ai` попадает в Formal AI через роутер, но если этот сервер сам обращается к API вендора, этот участок уходит из sidecar'а напрямую.
- **Инструменты, отличные от Claude, проверены слабее.** codex, gemini и qwen подключены к OpenAI-совместимому интерфейсу роутера через сгенерированную запись провайдера; сквозное подтверждение в `experiments/issue-2164/` есть только у Claude Code.
- **Псевдонимы моделей не принимаются.** Таблицы псевдонимов в роутере нет по замыслу ([router#192](https://github.com/link-assistant/router/issues/192)), и в добавлении разбора уровней он отказал, когда вопрос был поднят ([router#323](https://github.com/link-assistant/router/issues/323)), поэтому `--model sonnet` не работает там, где работает `--model claude-sonnet-4-5-20250929`. Начиная с `0.115.0` отказ перечисляет идентификаторы, которые развёртывание всё-таки объявляет, так что неверное имя подсказывает верное. Это касается всей поверхности с уровнями — `--plan`, `--escalate` и встроенные цепочки отката называют именно уровни, — поэтому в запуске с роутером указывайте датированные идентификаторы.
- **Роутер `1.x` не может опосредовать `gh`.** Его прокси GitHub живёт под `/api/services/github/api/v3`, а у `gh` нет настройки префикса пути, поэтому `gh api` и GraphQL уходят из задачи без посредника, тогда как `git` остаётся маршрутизированным. Достижимо только при явном выборе через `HIVE_MIND_ROUTER_IMAGE`; у закреплённой по умолчанию версии этого пробела нет ([router#415](https://github.com/link-assistant/router/issues/415)).
- **`HIVE_MIND_ROUTER_GITHUB=0` отключает маршрутизацию GitHub**, а у внешнего роутера (`HIVE_MIND_ROUTER_URL`) нет нашей сети контейнеров, в которой можно перехватывать, поэтому ему нужен `HIVE_MIND_ROUTER_GH_HOST`. В обоих случаях задача сохраняет собственные учётные данные `gh`, и её обращения к GitHub не опосредованы.

## Требования

- `--isolation docker`. Изоляция через роутер не имеет смысла без контейнера, который нужно изолировать.
- Docker с возможностью скачать `ghcr.io/link-assistant/router:0.119.0` (переопределяется через `HIVE_MIND_ROUTER_IMAGE`). Нижняя граница — `0.110.0`: более ранние версии пропускают принудительную отправку. Образы `1.x` тоже работают — с оговоркой про `gh` выше.
- Если до роутера не удаётся достучаться, задача **не запускается**. Откат к прямым учётным данным молча отменил бы ту самую изоляцию, ради которой запрашивался флаг.
