installed claude 2.1.316 / codex 0.166.0, synthetic credentials only. Every

provider with a throwaway CA; only package/binary download hosts are tunnelled.

configuration alone keeps sync off. Output carries counts and synthetic names only.

  - 0 account-sync / curated-catalog / hosted-connector requests or tunnels

CI run at e1082e83a and Run C (previous Codex release with different stock skills)
-------------------------------------------------------------------------------
docker-pr-check (run 41373932435, job 125080102833, host-socket image with
codex 0.164.0) passed P0-P2 and the first P3 checkpoint, then failed:
  ✅ P3 previous CLI releases installed (claude 2.1.309, codex 0.163.0): ...
  ❌ Codex stock runtime differs from the pristine pinned CLI 0.164.0 baseline.
     Restore verified stock content before launch; no repair is permitted.
Root cause: Codex rewrites ~/.codex/skills/.system on every version change, and
0.163.0 ships different stock skills from the 0.164.0 manifest that Hive pins
(src/codex-stock-skills.lib.mjs). Local separate BUN_INSTALL roots, first
start of each release (marker, file count, content sum):
  0.164.0: a49d0ab9dc3eb676 files=49 sum=cec178a965ad
  0.163.0: 3eadc798bef12c4a files=49 sum=b54e1acf48cc
  0.166.0: a49d0ab9dc3eb676 files=49 sum=cec178a965ad
  0.164.0: a49d0ab9dc3eb676 files=49 sum=cec178a965ad   (rewritten back)
Local Runs A/B used codex 0.166.0, so their "previous" release was 0.165.0,
which matches the pin; the CI image pins 0.164.0, so its previous is 0.163.0.
The refusal is the intended production behaviour (fail closed, no repair). The
gate now accepts exactly that typed CodexStockBaselineError, and only on the
two checkpoints where the staged release's skills are still materialized and
only when the staged release differs from the pin. The manifest, traffic and
canonical checks still run there, and every later checkpoint requires a fully
clean audit. Any other audit error or finding still fails the gate.

Production consequence: the idle updater installs @openai/codex@latest. A
future release whose stock skills differ from the pinned manifest makes Hive
refuse Codex launches until the pin/manifest is updated (fail closed, visible
error), rather than running unverified stock content.
