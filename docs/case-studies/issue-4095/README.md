# Issue 4095 — One Hive Mind maintenance entry point

[Issue #4095](https://github.com/link-assistant/hive-mind/issues/4095) describes an operator workflow split between five package executables, manual Docker instructions, and Control Center scripts that assume an existing administration environment. The same operation may need to run inside the image, on the Docker host, or on a remote Docker host reached from a developer machine.

## Evidence

- [Issue description and metadata](data/issue.json). At collection there were no issue comments, sub-issues, inline PR review comments, or PR reviews. The conversation on [PR #4096](https://github.com/link-assistant/hive-mind/pull/4096) contained earlier plans and execution trace links.
- The [Control Center source inventory](data/control-center-source-paths.txt) records the tree at commit [`21eb663e08fa6d1fa5751949d4534cd88818ac64`](https://github.com/link-assistant/hive-mind-control-center/tree/21eb663e08fa6d1fa5751949d4534cd88818ac64/src). Its [deployment notes](https://github.com/link-assistant/hive-mind-control-center/blob/21eb663e08fa6d1fa5751949d4534cd88818ac64/src/hive-control-center/docs/DEPLOY.md) and [requirements](https://github.com/link-assistant/hive-mind-control-center/blob/21eb663e08fa6d1fa5751949d4534cd88818ac64/src/hive-control-center/docs/REQUIREMENTS.md) describe the deployment variants, split configuration, handling of live tasks, and optional proxy.
- The Hive Mind baseline exposed `hive-cleanup`, `configure-claude`, `hive-screens`, `hive-models` and `close-linked-issues` through package bin links. The GitHub workflow example [calls the closing utility directly](../../../examples/workflows/close-linked-issues.yml). The solver and Telegram sweepers use the shared [issue-closing library](../../../src/post-merge-issue-closing.lib.mjs).

## Remaining migration and environment checks

The Control Center repository is outside this PR. Retiring it requires its maintainers to switch their deployment automation and validate the resulting workflow in the real environment. Its host-specific automation also does more than the portable manager currently implements. In particular:

- Its `auto-fix` coordinator scores and retries selected failures, repairs historical stores and classifies log/issue outcomes. The manager exposes the underlying start-command recovery actions and a local report with exit and memory evidence. The pinned start-command version already recovers empty or stale store locks. Automatic cross-task diagnosis, historical record rewrites, stuck upload remediation and GitHub incident reporting still require the existing tooling.
- Its archiver also maintains a GitHub destination repository, exports associated tool-result files, and applies extra identity redaction rules. The manager stages attributed JSONL and optional Links Notation copies for review. Automated publication, tool-result export, and the additional identity policy remain outside the manager.
- Its proxy diagnostics include client and server packet captures, reports, app tests, and authenticated phone/media tests. The portable manager implements deployment, TCP probes and bounded capture. Documented [media verification](https://github.com/link-assistant/hive-mind-control-center/blob/21eb663e08fa6d1fa5751949d4534cd88818ac64/src/hive-control-center/docs/MTProxy-VERIFICATION.md) needs a real proxy, a client network, and Telegram account/session access. No such credentials or deployment host were provided.
- The disposable Docker experiment uses a small fixture to exercise rollout mechanics. A released-image smoke, provider login and a live Telegram task test exercise real integrations beyond the fixture.

## Reproducing the verification

```bash
node --test tests/hive-manager-4095.test.mjs
node tests/test-docker-release-order.mjs
node tests/test-docs-language-sync.mjs
bash experiments/issue-4095/docker-lifecycle.sh
bash experiments/issue-4095/ssh-jumps.sh
```

The Docker experiment uses local fixtures and checks that image defaults are seeded once, Git and Codex data survive a replacement, bad bot configuration does not stop the active instance, a crashing candidate leaves the prior instance up, and rollback selects the earlier container. The SSH experiment starts disposable SSH servers to test two actual jumps without accepting unknown host keys.
