Keep one toolchain per language and stop hoarding superseded images (issue #2187).

A deployed host was carrying two Rust toolchains (`stable`, cached at a release **older** than the 1.96.0 pin next to it), a Node.js 20 the base image hardcodes while `engines.node` asks for >= 24 — so tasks re-downloaded their own node/bun into `/tmp` on every run — and 24 GB of reclaimable docker data that nothing ever collected. Meanwhile the disk gate stopped the run with `🛑 Stopping: no in-flight work can release disk space. Free space on this host (or enable --auto-cleanup) and rerun.`, naming none of it.

- **The image installs current runtimes and keeps exactly one of each.** `Dockerfile` and `Dockerfile.dind` pin `HIVE_MIND_NODE_VERSION`/`HIVE_MIND_BUN_VERSION`, re-install the base's global npm packages **at their existing versions** under the new node (the inherited playwright must keep matching the browsers already in `~/.cache/ms-playwright`), then delete every other version directory, so `node`, `nvm use default` and `/home/box/.node-bin` all resolve to the same runtime. `tests/test-issue-2187-runtime-versions.mjs` fails the build if the pin ever drops below the `engines.node` floor.
- **`.node-bin` pointed at the oldest node in the image.** `ls -d …/versions/node/v* | head -1` sorts lexicographically and ascending — with two versions installed it picked the older one, and text-sorted `v9` above `v22`. Now `sort -V | tail -1`.
- **`src/toolchain-inventory.lib.mjs`** classifies every version under `.rustup/toolchains`, `.nvm/versions/node`, `.pyenv/versions` and `.sdkman/candidates/*` from the filesystem alone (rustup's channel manifest, nvm's alias file, pyenv's `version`, SDKMAN's `current` symlink) — nothing is executed, so it is safe from a diagnostic. It is read-only by design and never proposes deleting a Rust *channel*: `cargo +stable` resolves through it, so a stale `stable` is reported as `rustup update stable`.
- **`src/docker-image-reclaim.lib.mjs` prunes what a rebuild superseded, and nothing else.** Dangling images plus strictly older tags of the Hive Mind repositories; never `latest`, never the newest tag of a repository, never the pinned isolation tag, never an image a container references, and never an image ID a protected tag also points at — so a host always keeps at least one reusable Hive Mind image after a deploy. Verified against a real daemon: with `latest`, `v2.17.0`, `v2.16.0` and an unrelated `postgres:15` installed, only `v2.16.0` was removed, and it was kept as soon as a container referenced it.
- **It runs on the same success path `--auto-cleanup` already owns** (new `--docker-image-reclaim=superseded|dangling|none` on `solve`, following `--auto-cleanup` when unset), and inside the disk gate, which now reclaims superseded images and re-checks free space before deferring a task.
- **`src/reclaimable-space.lib.mjs` answers "how much *could* be free".** Idle solver workspaces, orphaned agent snapshot stores (#2186), superseded images, `docker system df`'s own figure and superseded toolchains — measured, not estimated, with overlapping sources counted once and each one carrying the command that reclaims it. `hive` prints it at both stop sites and before exiting 75, so "free space on this host" finally says where.
- **Docker's `"+0000 UTC"` timestamps parsed as `null`**, which left tag ordering deciding which image was newest on its own — enough to keep an older build and remove a newer one. Fixed, with a regression test.

Upstream duplication was reported at [link-foundation/box#112](https://github.com/link-foundation/box/issues/112) and box fixed it in 2.7.0, which the base pins now use: `ghcr.io/link-foundation/box:2.7.0` and `ghcr.io/link-foundation/box-dind:2.7.0` ship one Node.js (v24.20.0), one Bun (1.4.2) and one Rust toolchain (`stable`, rustc 1.98.1) — verified by pulling and running both. They come from GHCR, box's registry of record, because Docker Hub's copy is broken: `konard/box:2.7.0` and `:latest` were written by box's amd64 job alone and carry no arm64 manifest (a regression — `konard/box:2.4.0` was multi-arch), and `konard/box-dind:2.7.0` does not exist there at all, since box's `docker manifest create` cannot combine per-architecture tags that its own mirror wrote as single-platform indexes. These images build for `linux/arm64` natively, so the Docker Hub tags are unusable; reported at [link-foundation/box#119](https://github.com/link-foundation/box/issues/119).

The runtime layer above the base stays even though 2.7.0 makes it a no-op: it is the version *floor*, and the base's versions are box's decision to change, not ours. The build steps that read the base reference out of the Dockerfiles now match any registry, so a pin can move again without a hardcoded `konard/box:` grep silently yielding an empty version.
