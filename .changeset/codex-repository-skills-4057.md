Codex runs in a repository with its own skills no longer fail with "Codex exposed skill instructions outside the capability allowlist" (#4057). Every skill under the checkout's `.agents/skills` and `.codex/skills` is admitted without an issue requirement. This includes skills linked from `.agents/skills` into `.claude/skills`, the layout used by Hive Mind's handoff and Playwright skills, as long as the file stays inside the checkout. Skills Codex discovers outside the checkout and the task `CODEX_HOME` (`$HOME/.agents/skills`, `/etc/codex/skills`, symlinks leaving the checkout) are now switched off for the task only, with `[[skills.config]] enabled = false` in the per-task `CODEX_HOME`, instead of failing the run. The catalog is then probed again, and the run still fails closed if Codex keeps showing them. Verbose logs list the trusted skill roots and each refused skill with its origin. Hosts still on 2.39.x should upgrade: the repository-skill fix from #3785 was versioned as 2.40.0/2.40.1, but neither version reached npm; 2.40.2 was the first published version with it.

The publication sanitizer also no longer masks an `Authorization:` header named in prose when the code span closes right after the colon. This text appears in the 2.40.2 release note, and masking it removed the closing backtick and broke the `` `Authorization: token <value>` `` example that followed on the same line. Real tokens stay masked (sensitive-data-sanitizer#177).

`@link-foundation/sensitive-data-sanitizer` 0.22.4 fixes the `ERR_SANITIZATION` failure on a letter run of about 4 MiB in text with emoji or other non-Latin-1 characters (sensitive-data-sanitizer#172), so Hive Mind's own long-run fallback is removed. `lino-i18n` 0.6.0 and `links-notation` 0.31.4 are also taken.
