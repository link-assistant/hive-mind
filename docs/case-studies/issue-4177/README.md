# Hive Mind and Up.computer

Research for [issue #4177](https://github.com/link-assistant/hive-mind/issues/4177). Snapshot taken on 2026-11-27 against Hive Mind 2.50.0 and Up.computer Core 0.0.41. The [source inventory](data/sources.md) records revisions, release evidence, upstream changes, and verification limits.

## Findings

Up.computer makes the path from conversation to delegated work unusually short. A chat can draft tasks, create a worker, and receive a result or a blocked notification. Workers select work by project, status, and tags, and bots add persistent, editable memory and private conversations. It couples that workflow to a local-first desktop client, provider sessions, and a browser client that can connect to a user-controlled host. The published release, product flags, and live download page establish different boundaries for desktop, hosted access, and inherited mobile code. [Up.computer evidence](data/sources.md#upcomputer)

Hive Mind's strongest workflow starts with work a team already tracks in GitHub. It can select eligible issues across repositories, fork and prepare a branch and draft PR, resume after CI or review feedback, and check fresh merge prerequisites and issue coverage. Telegram gives users remote control of execution. Docker task controls, the model catalogue, and `hive-manager` provide operator tools. The missing link is a consistent model of **who should pick up a task, what happened across retries, and where the human should respond**, especially across repos and workers. [Hive Mind evidence](data/sources.md#hive-mind)

The recommended first investment is **durable worker routing and handoffs for GitHub Issues**, with GitHub PRs, checks, and Projects as the team interface and Telegram or CLI for execution controls. Keep scheduled work, agent session review, and operator controls independently deployable. Use targeted pilots to decide whether a small run viewer, agent personas, or local-first workflows close enough unmet needs to justify their costs. [Roadmap](roadmap.md)

## How to use the comparison

A feature is a user outcome. Similar results may come from very different workflows, such as inspecting a GitHub PR from a phone versus continuing a conversational thread with a worker on a paired host. The matrix gives both products credit for the outcomes their evidence supports and calls out the difference when that affects adoption.

The research is based on public source, documentation, release assets, and public product pages. The study uses upstream screenshots as evidence for the bot mention UX. Binary installation, authenticated and managed service behavior, and comparative speed, cost and reliability are subjects for the controlled pilot in the roadmap.
