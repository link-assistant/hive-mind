Root cause:
  The terminal's selected registered writer obtains checkpoint clientHistory
  through GeminiClient.getHistory(). Native role coalescing combines the initial
  session context and original user prompt. Restore records that combined turn;
  the native session loader later filters the whole context-prefixed turn.

  executable caches, native recorder formats and unselected writers are retained.
  The package version, prerequisite hashes and unique source context are checked
  before mutation; --check does not modify the disposable package.

The third terminal waits for the native resumed input UI before submitting its
interactive prompt. The initial experiment using --prompt-interactive exposed
a separate native startup race: that prompt can dispatch before resume finishes
and subsequent recording can refuse. That automatic path is not fixed by this
checkpoint repair and remains an explicitly unfinished criterion.

The actual CLI entry, PTY, checkpoint serializer, Git service, chat, recorder,
session loader and model requests execute without native exports or SDK methods
instrumented. Credentials and provider responses are synthetic; TLS verification
stays enabled through the loopback provider. Data/heap/stack, phase, request and
diagnostic limits are finite, and whole process groups are stopped and reaped.
The experiment does not install a production adapter. Complete native writers,
plan/task memory, migrations, interrupted/power-loss durability, all-backend
lifecycle and production package/image/launcher integration remain unfinished.
